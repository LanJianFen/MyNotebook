*   **`Horizon Occlusion` 解决的是【反射光线 $\mathbf{R}$ 或入射光 $\mathbf{L}$】穿透进宏观几何表面地平线以下（漏光）的问题（把漏到地下的光直接乘以 $0$ 抹杀，属于“截断并消灭高光”）！**

我们用纯几何向量（区分**宏观几何法线 $\mathbf{N}_{\text{geom}}$** 与 **法线贴图扰动后的着色法线 $\mathbf{N}_{\text{shading}}$**），把这两个概念彻底掰开讲清楚！

### 一、 案发现场：为什么叫“地平线漏光（Light Leaking Below the Horizon）”？

在渲染中，一个像素上其实有**两根法线**：
1. **宏观几何法线 $\mathbf{N}_{\text{geom}}$（或顶点法线 $\mathbf{N}_{\text{vertex}}$）**：这是三角形网格自己真实的物理朝向。它定义了**真正的“宏观地平线（Horizon）”**——任何方向向量 $\boldsymbol{\omega}$，如果 $\boldsymbol{\omega} \cdot \mathbf{N}_{\text{geom}} < 0$，说明这根光线是从这块三角形网格的**地下（模型内部）**钻出来的！
2. **着色法线 $\mathbf{N}_{\text{shading}}$**：这是从法线贴图（Normal Map）里采样出来、被强行歪曲后的虚拟法线。

```
          视线 V                 着色法线 N_shading (被法线贴图严重向右倾斜)
             \                      /
              \                    /
===============\==================*================  <-- 真正的宏观几何表面 (法线 N_geom 垂直向上)
                \                / \
                 \              /   \  <-- 反射向量 R = reflect(-V, N_shading)
                  \            /     \     注意！R 扎进宏观地平线以下了 (dot(R, N_geom) < 0)！
                   \          /       v
                    [模型内部 / 地下]
```

**请看上面这幅几何图，灾难是如何发生的：**
1. 你以一个比较平的角度（$\mathbf{V}$）看向一块平铺在地面上的地板（宏观法线 $\mathbf{N}_{\text{geom}}$ 笔直朝上，此时 $\mathbf{N}_{\text{geom}} \cdot \mathbf{V} > 0$，完全合法）。
2. 这块地板贴了一张凹凸强烈的法线贴图，当前像素的着色法线 $\mathbf{N}_{\text{shading}}$ 往远离你的方向大幅度倾斜（但注意：此时 $\mathbf{N}_{\text{shading}} \cdot \mathbf{V}$ **依然大于 0**！连 `abs()` 都没触发！）。
3. 现在，你要计算镜面反射（尤其是采样 IBL 环境贴图 Cubemap）：
   你用视线 $\mathbf{V}$ 围绕着色法线 $\mathbf{N}_{\text{shading}}$ 求反射向量：
   $$ \mathbf{R} = \text{reflect}(-\mathbf{V}, \mathbf{N}_{\text{shading}}) = 2(\mathbf{N}_{\text{shading}} \cdot \mathbf{V})\mathbf{N}_{\text{shading}} - \mathbf{V} $$
4. **物理车祸发生了：**
   因为 $\mathbf{N}_{\text{shading}}$ 歪得太厉害，反弹出去的这根反射光线 $\mathbf{R}$，**直接一头扎进了宏观几何表面的下方（即 $\mathbf{R} \cdot \mathbf{N}_{\text{geom}} < 0$）！**

**如果不加拦截会发生什么？**
*   在现实物理世界中，如果这是一个真凹凸几何体，这根向下反弹的光线会**撞在地板自己的地面上**被挡死。
*   但在引擎里，法线贴图没有真实几何体阻挡！这根扎进地下的反射向量 $\mathbf{R}$，会直接穿透地板模型，**去采样天空盒（Cubemap）下半球的地底亮光**，或者接收来自模型背面（地下）的光源 $\mathbf{L}$！
*   **视觉后果**：你会看到模型背光的暗部边缘，突然泛出一圈极其诡异、仿佛模型是透明玻璃一样的“幽灵漏光亮边”！

### 二、 什么是真正的 Horizon Occlusion（地平线遮蔽）数学公式？

为了消灭这根“扎进宏观地平线以下”的非法反射光，**Jeff Russell（Marmoset Toolbag 八猴渲染器的联合创始人）** 提出了著名的 **Horizon Occlusion（地平线高光遮蔽）**，随后被 **Sébastien Lagarde 收录进 Frostbite 2014 白皮书（Section 4.10.2 / Specular occlusion）** 以及 Unity HDRP 中。

它的核心思想极其简单直接：
**检查反射光线 $\mathbf{R}$（或直接光 $\mathbf{L}$）与【宏观几何/顶点法线 $\mathbf{N}_{\text{geom}}$】的点乘！一旦发现 $\mathbf{R} \cdot \mathbf{N}_{\text{geom}} < 0$（低于宏观地平线），就直接用一个平滑衰减因子把高光掐死归零！**

#### Marmoset / Frostbite 的标准数学公式：
给定反射向量 $\mathbf{R} = \text{reflect}(-\mathbf{V}, \mathbf{N}_{\text{shading}})$ 和宏观顶点法线 $\mathbf{N}_{\text{vertex}}$，以及控制衰减柔和度的参数 `horizonFade`（通常取 `1.3` 左右）：

$$ h = \text{saturate}\left( 1.0 + \text{horizonFade} \cdot (\mathbf{R} \cdot \mathbf{N}_{\text{vertex}}) \right) $$
$$ \text{HorizonOcclusion} = h^2 $$

**我们代入数值看看它是怎么工作的：**
1. **当反射光线正常朝向天空时（$\mathbf{R} \cdot \mathbf{N}_{\text{vertex}} > 0$）**：
   $1.0 + \text{正数} > 1.0$，经过 `saturate` 后 $h = 1.0$，$\text{HorizonOcclusion} = 1.0$（完全不遮挡，高光 100% 通过）。
2. **当反射光线刚刚越过宏观地平线扎进地下时（$\mathbf{R} \cdot \mathbf{N}_{\text{vertex}} < 0$）**：
   随着点乘变得越来越负，$1.0 + \text{horizonFade} \cdot (\text{负数})$ 迅速从 $1.0$ 降到 $0.0$，平方后平滑地把漏向地下的高光能量**彻底乘以 $0$ 抹杀掉**！

```hlsl
// ===================================================
// Marmoset / Frostbite 2014 标准：Horizon Occlusion (地平线高光遮蔽)
// 专门用于解决法线贴图 (N_shading) 导致反射向量 R 扎入宏观几何表面 (N_vertex) 以下引发的边缘漏光
// ===================================================
half ComputeHorizonOcclusion(half3 R, half3 N_vertex, half horizon_fade)
{
    // 当 dot(R, N_vertex) < 0 时，说明反射光扎进了宏观地平线以下，开始平滑衰减至 0
    half horizon = saturate(1.0h + horizon_fade * dot(R, N_vertex));
    return horizon * horizon;
}
```
*(同理，对于直接光源 $\mathbf{L}$，引擎除了检查着色法线 `saturate(dot(N_shading, L))` 外，还会额外乘上一个宏观几何法线的软截断 `saturate(dot(N_vertex, L) * 5.0)`，确保背对宏观三角形的光源绝对不可能因为法线贴图的倾斜而照亮背面像素！)*

### 三、 终极对比表：彻底分清这两个概念

现在把这两个操作并排放在一起，你再也绝不会把它们搞混了：

| 对比维度 | `abs(dot(N_shading, V)) + 1e-5h` | `Horizon Occlusion` (地平线遮蔽) |
| :--- | :--- | :--- |
| **需要几根法线参与？** | **只需 1 根**（着色法线 $\mathbf{N}_{\text{shading}}$）。 | **必须 2 根对比**（着色法线算出的 $\mathbf{R}$ vs 宏观顶点法线 $\mathbf{N}_{\text{vertex}}$）。 |
| **针对的是哪个向量？** | 摄像机**视线向量 $\mathbf{V}$**。 | 弹出去的**反射光线 $\mathbf{R}$**（或入射光 $\mathbf{L}$）。 |
| **解决什么 Bug？** | 像素明明可见，但法线贴图太歪导致 $\mathbf{N}_{\text{shading}} \cdot \mathbf{V} \le 0$，引发 $V$ 项**分母除零 `NaN` 或高光出现死黑断层**。 | $\mathbf{N}_{\text{shading}} \cdot \mathbf{V} > 0$ 没问题，但反弹出的光线 $\mathbf{R}$ 扎进了模型内部（$\mathbf{R} \cdot \mathbf{N}_{\text{vertex}} < 0$），引发**模型暗部边缘出现透明幽灵漏光**。 |
| **数学动作是什么？** | **“起死回生”**：把负的点乘镜像翻回正数，保住高光连续性。 | **“赶尽杀绝”**：把扎入地平线以下的反射光平滑乘上 $0$ 抹杀掉。 |

一句话总结：**`abs(NdotV)` 是为了防止算术崩溃而救活视线；`Horizon Occlusion` 是为了防止物理穿模而掐死越过宏观地平线的反射光！** 这下彻底分清楚了吧？!]
