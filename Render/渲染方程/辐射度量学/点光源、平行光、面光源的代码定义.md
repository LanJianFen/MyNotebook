在现代商业游戏引擎（如 Unreal、Unity 的 SRP、Frostbite）中，定义光源有一个**铁律**：
**CPU 端的数据结构服务于“人（美术/物理定义）”，GPU 端的数据结构服务于“机器（极致的 ALU 算力优化）”。**

我们绝对不会把美术在面板里填的数值原封不动地传给 GPU。我们会在这里做一层**预计算（Pre-computation）和数据打包（Data Packing）**。

下面我用 C++ 和 HLSL 伪代码，为你展示这三种光源在工业级渲染器中是如何被定义的。

---

### 1. 平行光 (Directional Light)

**核心逻辑：** 抛弃距离，只留方向。CPU 填 Lux（勒克斯），GPU 直接拿到预乘好的 Irradiance。

**C++ 端 (运行在 CPU 上，面向美术)：**
```cpp
struct CPUDirectionalLight {
    Vector3 direction;      // 美术旋转光源产生的方向
    Vector3 color;          // 光源颜色 (RGB, 归一化)
    float   intensity_lux;  // 物理强度，单位：Lux (例如阳光 100000)
    
    // 阴影参数...
    int cascade_count;
    // ...
};
```

**预计算与转换 (CPU -> GPU)：**
```cpp
GPUDirectionalLight PackForGPU(const CPUDirectionalLight& cpuLight) {
    GPUDirectionalLight gpuLight;
    // 1. 方向取反并归一化 (Shader 里 L 向量是 指向 光源的)
    gpuLight.L_dir = Normalize(-cpuLight.direction);
    // 2. 颜色和物理强度提前合并！GPU 就不需要再做乘法了
    gpuLight.Irradiance = cpuLight.color * cpuLight.intensity_lux; 
    return gpuLight;
}
```

**HLSL / GLSL 端 (GPU Constant Buffer)：**
```hlsl
struct GPUDirectionalLight {
    float3 L_dir;       // 指向光源的方向
    float3 Irradiance;  // 已经乘好 Lux 的垂直辐照度 E_perp
};
// Shader 里的计算： L_o = f_r * Irradiance * max(0, dot(N, L_dir));
```

### 2. 点光源 (Point Light)

**核心逻辑：** CPU 输入流明（Lumens）和影响半径，CPU 负责除以 $4\pi$ 转成 Radiant Intensity。同时 CPU 要提前算好衰减边界，防止 GPU 做昂贵的计算。

**C++ 端 (面向美术)：**
```cpp
struct CPUPointLight {
    Vector3 position;       // 世界坐标
    Vector3 color;          // 光源颜色
    float   power_lumens;   // 物理总通量，单位：流明 (Lumens)
    float   source_radius;  // 发光球体半径 (用于防止 1/d^2 奇点溢出)
    float   falloff_radius; // 最大影响半径 (超出这个范围光照强制为0，用于性能剔除)
};
```

**预计算与转换 (CPU -> GPU)：**
```cpp
GPUPointLight PackForGPU(const CPUPointLight& cpuLight) {
    GPUPointLight gpuLight;
    gpuLight.Position = cpuLight.position;
    
    // 核心转换： Lumens -> Radiant Intensity (I = Phi / 4PI)
    float intensity = cpuLight.power_lumens / (4.0f * PI);
    gpuLight.Intensity = cpuLight.color * intensity; // 预乘颜色
    
    gpuLight.SourceRadiusSq = cpuLight.source_radius * cpuLight.source_radius;
    // 预计算半径的倒数平方，供 GPU 算距离截断 (Distance Windowing)
    gpuLight.InvFalloffRadiusSq = 1.0f / (cpuLight.falloff_radius * cpuLight.falloff_radius);
    
    return gpuLight;
}
```

**HLSL / GLSL 端 (GPU Structured Buffer)：**
```hlsl
struct GPUPointLight {
    float3 Position;
    float3 Intensity;          // 已经是 Radiant Intensity (I)
    float  SourceRadiusSq;     // 防奇点用的 e^2
    float  InvFalloffRadiusSq; // 1 / R^2，用于计算衰减曲线
};

// Shader 里算 E_perp 的高效写法 (伪代码)：
// float3 L_vec = Light.Position - WorldPos;
// float d2 = dot(L_vec, L_vec);
// float distance_attenuation = 1.0 / (max(d2, Light.SourceRadiusSq));
// float windowing = Square(saturate(1.0 - Square(d2 * Light.InvFalloffRadiusSq)));
// float3 E_perp = Light.Intensity * distance_attenuation * windowing;
```

### 3. 普通面光源 (Area Light - 以最常用的矩形光 Rect Light 为例)

**核心逻辑：** 面光源是“带面积”的。它不再是点或方向，而是一个空间多边形。它的物理单位不再是 Intensity，而是 **Radiance（辐射率，$L$）**。

**C++ 端 (面向美术)：**
```cpp
struct CPURectLight {
    Vector3 position;       // 中心点
    Vector3 direction;      // 面朝向 (Normal)
    Vector3 up_vector;      // 顶部朝向 (用于确定面的旋转)
    float   width;          // 宽
    float   height;         // 高
    Vector3 color;          // 颜色
    float   power_lumens;   // 整体发出的光通量 (Lumens)
};
```

**预计算与转换 (CPU -> GPU)：**
```cpp
GPURectLight PackForGPU(const CPURectLight& cpuLight) {
    GPURectLight gpuLight;
    gpuLight.Position = cpuLight.position;
    gpuLight.Normal = Normalize(cpuLight.direction);
    gpuLight.Right = Normalize(Cross(cpuLight.up_vector, gpuLight.Normal));
    gpuLight.Up = cpuLight.up_vector;
    
    gpuLight.HalfWidth = cpuLight.width * 0.5f;
    gpuLight.HalfHeight = cpuLight.height * 0.5f;

    // 核心转换：对于一个理想漫反射的面光源，流明 -> 辐射率 Radiance
    // L = Phi / (Area * PI)
    float area = cpuLight.width * cpuLight.height;
    float radiance = cpuLight.power_lumens / (area * PI);
    gpuLight.Radiance = cpuLight.color * radiance; 
    
    return gpuLight;
}
```

**HLSL / GLSL 端：**
```hlsl
struct GPURectLight {
    float3 Position;
    float3 Normal;
    float3 Right;
    float3 Up;
    float  HalfWidth;
    float  HalfHeight;
    float3 Radiance; // 表面发出的 Radiance，即 L_i
};
```
**🚨 渲染工程师特别提醒（面光源的评估差异）：**
你在 Shader 里**不能**像点光源那样简单地写个公式计算面光源！
*   如果是**光线追踪（Path Tracing）**：我们需要在 `HalfWidth` 和 `HalfHeight` 构成的矩形内随机生成一个点，向它发射光线，命中后返回 `Radiance`，并除以概率密度 `PDF (1/Area)`。
*   如果是**实时光栅化（Rasterization）**：面对一个矩形，它在着色点上形成的多边形立体角非常复杂。现代引擎会使用极其硬核的 **LTC (Linearly Transformed Cosines)** 算法。我们会将材质 BRDF 拟合成一个矩阵，把面光源多边形的顶点乘上这个矩阵，然后在多边形内部进行解析积分。

### 总结：引擎灯光架构的本质

如果你自己写引擎，通常会有一个基类 `LightComponent`。但最终推送到 GPU 时，我们会把所有灯光塞进不同的**线性数组（Structured Buffers）**中：

```hlsl
// GPU 最终拿到的数据布局
StructuredBuffer<GPUDirectionalLight> DirLights;
StructuredBuffer<GPUPointLight>       PointLights;
StructuredBuffer<GPURectLight>        RectLights;

// 为什么分开存放？
// 因为它们在 Shader 里用的完全是三套不同的物理方程和数学代码！
```

*   **Directional Light** 是全屏的解析光照，只需简单的乘法。
*   **Point Light** 是局部的解析光照，多了一步距离求逆和衰减。
*   **Area Light** 是连续积分光照，需要用到立体角采样或 LTC 矩阵计算。
