你问得非常精准：既然第二个乘数（面积积分）用 LUT 解决了，那第一个乘数 **$\frac{1}{\pi} F_t(x_o, \omega_o)$** 到底去哪了？它是怎么算的？

答案是：**它在现代 Shader 里，被拆解成了两个极其基础的常识性操作，甚至隐蔽到你可能每天都在写，却没意识到那就是它！**

我们把 $\frac{1}{\pi} F_t(x_o, \omega_o)$ 掰成两半来看，对应着 Shader 里的两行代码：

---

### 第一半：$F_t(x_o, \omega_o)$ 去哪了？

$F_t(x_o, \omega_o)$ 的物理意义是：**次表面散射的光在肉里散开后，跑到出射点 $x_o$，想要射进摄像机（方向 $\omega_o$）时，有多少比例的光能突破皮肤表面的界限“透射”出来。**

在图形学中，有一个雷打不动的能量守恒定律：
**透射率 ($F_t$) + 反射率 ($F_r$) = 1**。

*   **$F_r$ 是什么？** 就是高光反射！就是你在写任何 PBR Shader 时，必定会用的 **菲涅尔方程（Fresnel Schlick 近似）**。
*   它的自变量是出射点法线 $\mathbf{N}$ 和观察方向 $\mathbf{V}$（也就是你的 $\omega_o$）。

所以，$F_t(x_o, \omega_o)$ 在代码里，就是极其简单的：
`1.0 - Fresnel(Normal, ViewDir)`

**这就对应了我在上一条伪代码里写的这一句：**
```glsl
// 这就是你的 Ft(xo, wo) ！
float transmittance = 1.0 - Fresnel_reflect; 
```
引擎不需要查表，也不需要算积分，直接在当前像素上，拿相机的 `ViewDir` 和法线做个点乘算个菲涅尔，然后用 1 去减，第一个乘数的核心部分就搞定了！

---

### 第二半：那个常数 $\frac{1}{\pi}$ 去哪了？

在图形学公式里，看到 $\frac{1}{\pi}$，你的第一反应应该是什么？
**是 Lambert（兰伯特）漫反射！**

所有的纯漫反射（完全散开的光），在向半球空间发射能量时，为了保证能量总和加起来等于 1（白炉测试），都必须除以 $\pi$。

在实际的游戏引擎（比如 UE 或 Unity）底层的代码结构中，这个 $\frac{1}{\pi}$ 有两种隐藏方式：

1.  **被吃进基础光照（Light Attenuation）里了：** 很多引擎在计算灯光的时候，会统一在光源的亮度公式里预先除以 $\pi$。
2.  **被合并到 Albedo（反照率）里了：** 在标准的 PBR 着色器中，Diffuse 项的标准写法其实是 `(Albedo / PI)`。

所以，那个 $\frac{1}{\pi}$ 并不是什么高深的东西，它就是一个**归一化常数**，确保算出来的颜色不会比光源本身还要亮。

---

### 把两部分合起来：最终的真实代码映射

我们把你提问的这个宏大公式：
$L_o = \left[ \frac{1}{\pi} F_t(x_o, \omega_o) \right] \times \left[ \text{LUT} \right]$

无缝翻译成 GPU 里运行的最终 Cg/HLSL 代码，其实就是这短短两行：

```glsl
// 1. 获取面积积分的结果 (你的第二个乘数)
float3 SSS_Integral = tex2D(LUT, float2(NdotL, Curvature)).rgb * Albedo;

// 2. 乘上透射率 Ft (你的第一个乘数的一部分)
// 3. 乘上 1/PI (你的第一个乘数的常数部分)
float3 Final_SSS_Light = SSS_Integral * (1.0 - Fresnel_Schlick(N, V)) * (1.0 / PI);
```

这就是第一项的最终归宿！
