

这是一个非常经典的图形学问题！

直觉上，**切线（Tangent）** 和 **法线（Normal）** 一样，都是空间中的一个方向向量，理应只需要 $x, y, z$ 三个分量就够了。

那多出来的第 4 个分量 **$w$** 是干嘛的？

**答案：它的作用是用来决定“副切线（Binormal / Bitangent）”的方向。**

为了理解这一点，你需要知道法线贴图（Normal Mapping）背后的一个核心概念——**切线空间（Tangent Space）**。

---

### 1. 切线空间的三剑客

要在模型表面正确计算光照（特别是凹凸感），我们需要在这个顶点的表面建立一个局部坐标系。这个坐标系由三个互相垂直的轴组成：

1.  **Normal ($N$)**: 法线（垂直于表面，蓝色轴）。
2.  **Tangent ($T$)**: 切线（沿着纹理 $U$ 方向，红色轴）。
3.  **Binormal ($B$)**: 副切线（沿着纹理 $V$ 方向，绿色轴）。有时也叫 Bitangent。

这三个轴必须**两两垂直**。

### 2. 为什么需要存 $w$？

在数据存储优化中，我们发现：
*   我们已经存了 **法线 ($N$)**。
*   我们已经存了 **切线 ($T$)**。

根据几何学知识，如果已知两个垂直向量，第三个向量（$B$）可以通过 **叉乘（Cross Product）** 自动算出来！
$$B = N \times T$$

**但是！有一个巨大的坑：镜像对称（Mirroring）。**

设想一下你做了一个人体模型，为了节省贴图空间，你只画了左半边的 UV，右半边的 UV 是直接镜像翻转过去的。
*   在左半边，$B$ 轴可能朝上。
*   在镜像的右半边，由于纹理 UV 翻转了，$B$ 轴应该朝下！

单纯的 $N \times T$ 算出来的方向永远是固定的（符合右手定则），它**无法自动识别模型是否被镜像了**。如果不管它，镜像那一边的法线贴图就会反向（凹进去变凸出来）。

### 3. $w$ 分量的救场机制

为了解决镜像问题，Unity（以及大多数游戏引擎）在切线的 $w$ 分量里存了一个符号标记：

*   **$w = 1$**: 表示正常的坐标系（未镜像）。
*   **$w = -1$**: 表示镜像反转的坐标系。

### 4. 最终的 Shader 计算公式

在 Shader 的顶点着色器里，我们不直接读 Binormal，而是用这个公式现场算出来：

```hlsl
// HLSL 代码片段
float3 normal = v.normal;
float4 tangent = v.tangent;

// 1. 算出副切线方向 (Binormal)
// 这里的 tangent.w 就是那个 1 或 -1
float3 binormal = cross(normal, tangent.xyz) * tangent.w;

// 2. 构建 TBN 矩阵 (用于把切线空间转到世界空间)
float3x3 TBN = float3x3(tangent.xyz, binormal, normal);
```

### 总结
之所以 Tangent 是 4 个分量（Float32 * 4）：
*   **前 3 个 ($x, y, z$)**：描述切线的**方向**。
*   **第 4 个 ($w$)**：描述坐标系的**手性（正向还是反向）**，专门用来修正在**镜像 UV** 模型上法线贴图反向的 Bug。
