

这是一个非常经典且直击计算机图形学（Computer Graphics）核心的问题。

一句话直接回答：**为了“欺骗”你的眼睛，用原本是平面的三角形，模拟出圆滑的曲面（Smooth Shading）。**

如果法线定义在面（Face）上，你永远只能得到“硬棱角”的效果；而定义在顶点（Vertex）上，我们既可以做硬棱角，也可以做平滑过道。

下面我们深度拆解一下这个机制。

### 1. 根本原因：插值（Interpolation）

在渲染管线中，顶点着色器（Vertex Shader）处理完顶点后，会进入**光栅化（Rasterization）**阶段。

在这个阶段，GPU 会把三角形三个顶点的属性（位置、UV、颜色、**以及法线**）进行“混合”，算出一个渐变值赋予给三角形内部的每一个像素。

#### 假设法线定义在“面”上 (Flat Shading)
*   这意味着这一个三角形内，所有像素的法线方向是**完全一致**的。
*   **结果：** 光照计算结果也是一致的。
*   **视觉效果：** 你能清晰地看到三角形的边缘。两个相邻的三角形之间，光照会发生瞬间的“跳变”。看起来就像钻石或者 90 年代的老游戏（低模风格）。

#### 假设法线定义在“顶点”上 (Smooth Shading / Phong Shading)
*   我们可以把一个顶点周围所有相邻三角形的法线取个**平均值**，赋给这个顶点。
*   **过程：**
    *   顶点 A 法线朝左上，顶点 B 法线朝右上。
    *   当 GPU 渲染 A 和 B 中间的像素时，它会自动**线性插值**：`Normal = lerp(NormalA, NormalB, t)`。
    *   中间像素的法线会平滑地从左上过渡到右上。
*   **结果：** 光照计算也会随着像素位置平滑过渡。
*   **视觉效果：** 虽然几何体依然是有棱角的三角形，但在光照下，它看起来像是一个完美的圆球或曲面。

### 2. 示意对比

想象你要渲染一个球体（用几百个三角形拼成的）：

*   **面法线（Face Normals）：** 看起来像个迪斯科球（Disco Ball），全是反光的小镜子片。
*   **顶点法线（Vertex Normals）：** 看起来像个台球，表面光滑圆润。

因为在现实游戏中，绝大多数物体（角色皮肤、车漆、地形）都需要“看起来是圆的”，所以图形学标准选择将法线存储在顶点上，以便进行插值。

### 3. 那如果我真的想要“硬棱角”怎么办？（比如立方体）

这就引出了 Unity 开发中常遇到的一个概念：**拆分顶点（Vertex Splitting）**。

如果你导入一个 Cube（立方体）到 Unity，你会发现它有 24 个顶点，而不是数学上的 8 个顶点。为什么？

因为**一个顶点只能存一个法线**。

*   **对于立方体的一个角：**
    *   对于“上面”的三角形，这个角需要一个**朝上**的法线。
    *   对于“前面”的三角形，这个角位置需要一个**朝前**的法线。
    *   对于“右面”的三角形，这个角位置需要一个**朝右**的法线。

为了解决这个冲突，建模软件（Blender/Maya）和游戏引擎会把这个角**拆分成 3 个位置重合、但法线不同**的顶点。

### 4. Unity 中的实际控制

你在 Unity 的 Model Import Settings 里经常看到这个选项：
**Normals: Import** 或 **Calculate**。

底下通常有个 **Smoothing Angle (平滑角度)** 滑动条：

*   **原理：** Unity 会检查相邻两个面的夹角。
*   **如果夹角 < 60度：** 认为这是个曲面，就把这两个面共用的顶点合并，法线取平均（看起来圆滑）。
*   **如果夹角 > 60度：** 认为这是个硬棱角，就在这里断开，把顶点拆成两个，各自保持各自面的法线方向（看起来有棱角）。

### 总结

之所谓定义在顶点上，是因为：
**这是数据结构的一种超级红利——用极少的几何数据（低模），配合 GPU 的自动插值能力，通过法线的平滑过渡，在视觉上伪造出高精度的曲面模型。**
