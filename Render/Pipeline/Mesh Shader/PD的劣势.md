

这是一个极其关键的底层硬件问题！你问到了传统管线硬件架构中最核心的痛点。

直接回答你的问题：**PD（Primitive Distributor，图元分发器）是在 Vertex Shader（顶点着色器）执行【之前】工作的！** 

准确地说，PD 是传统 GPU 硬件中 **Input Assembler（IA，输入装配器）** 阶段的绝对核心大脑。它负责在 GPU 的前端读取指令，然后把任务打包，**分发（Distribute）给后端的计算单元（SM）去执行 Vertex Shader**。

为了让你彻底弄懂，我们用“工厂流水线”的比喻，把传统 GPU 内部真实的物理执行顺序捋一遍：

### 传统 GPU 的物理执行顺序（一帧的诞生）

**第一步：指令入场（CPU -> GPU Front End）**
CPU 调用 `DrawIndexed`，把几十万个索引构成的 Index Buffer 送进 GPU。

**第二步：PD 疯狂切块打包（这就是前面说的“第一大原罪”）**
此时，**Vertex Shader 还没开始运行**。
面对庞大的全局索引，硬件模块 PD 首当其冲。它就像一个分拣流水线上的包工头，飞速地读取这几十万个索引，一边读一边做我们在那张图上看到的事情：
1. 提取出最多 32 个“唯一顶点（Unique Vertices）”。
2. 把原有的全局三角形索引，改写成基于这 32 个顶点的“局部索引（Local Indices 0~31）”。
3. 当凑满 32 个顶点，或者凑满 32 个三角形时，PD 就会把这个打包好的“批次（Batch）”盖个章，准备发车。

**第三步：把批次派发给计算核心（触发“第二大原罪”）**
PD 把打包好的 Batch，发送给 GPU 的流式多处理器（SM）。
SM 接收到 Batch 后，会启动一个 **Warp（线程束，包含 32 个线程）**。
*   **这就解释了为什么会有线程空转**：如果 PD 发来的这个 Batch 里，虽然装满了 32 个三角形，但因为顶点高度复用，**里面只有 10 个唯一顶点**。
*   那么 SM 分配出来的这 32 个线程中，**只有 10 个线程拿到了顶点数据，剩下的 22 个线程只能干瞪眼（空转）。**

**第四步：执行 Vertex Shader**
那 10 个拿到顶点数据的线程，开始真正执行你写的 Vertex Shader 代码（MVP变换、骨骼蒙皮等）。这就是为什么说“每个唯一顶点算一次”，因为 PD 已经在发车前（第二步）帮你把这个批次里的重复顶点去掉了。

**第五步：图元装配与光栅化（Primitive Assembly & Rasterization）**
这 10 个线程算完 MVP 坐标后，GPU 里的固定硬件会拉出 PD 在第二步做好的“局部索引（0~31）”，把刚算好的这 10 个顶点拼成 32 个三角形，然后送给光栅化器去画像素。

---

### 为什么 PD 绝对不可能在 VS 之后？

你反过来想一下：
如果 PD 在 VS 之后，意味着 GPU 得盲目地顺着 Index Buffer，见一个索引就发一个线程去跑 VS。
比如索引是 `[1, 2, 3,  2, 3, 4]`。
如果不经过 PD 提前查重和打包，GPU 就会傻傻地派发 6 个线程：
线程1算顶点1，**线程2算顶点2，线程3算顶点3，线程4算顶点2，线程5算顶点3**，线程6算顶点4。
发现了吗？**顶点 2 和 3 被毫无意义地执行了两次极具毁灭性的 VS 运算！**

正因为 GPU 为了**尽可能地在执行 VS 时省下算力（同一个 Batch 里不重复算）**，它才被迫发明了 PD 这个硬件模块，**在进入 VS 之前**，死命地把流水线截断，强行把全局的一长串索引切成一个个毫无瓜葛的 32 人小分队（Batch）。

### 总结：Mesh Shader 到底替代了什么？

理解了 PD 在“最前端”工作，你就能彻底明白 Mesh Shader 的伟大了：

*   **传统管线**： CPU -> 【**PD 硬件实时切块打包**】 -> 【分发 Warp】 -> 【部分线程可能空转执行 VS】 -> 【硬件组装三角形】 -> 【光栅化】。
*   **Mesh Shader 管线**： CPU (离线把模型切成 Meshlet 存好) ->  GPU 运行时直接读 Meshlet -> 【Task Shader / Mesh Shader 灵活调度线程，全员满载拉取顶点和局部索引】 -> 【**开发者自己写代码组装三角形**】 -> 【光栅化】。

Mesh Shader 相当于对 GPU 硬件工程师说：**“你们设计的 PD 这个前端打包模块太蠢、太慢、太浪费晶体管了！把它给我砸了！以后模型切块的工作，我在游戏打包编译时就用 CPU 提前做好了（Meshlet）。在 GPU 运行时，别再搞什么固定流水线包工头了，直接用 Compute 通用计算单元，把这些预制好的小块按需拉过来算，算完直接糊在光栅化器上！”**
