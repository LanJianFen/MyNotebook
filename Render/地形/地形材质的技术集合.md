

**Texture Splatting（纹理泼溅/混合）** 是 3D 地形渲染中最基础也最核心的表面着色技术。

简单来说，它的核心思想是：**与其试图制造一张巨大的、覆盖整个世界的 8K 纹理（那样显存会爆炸且细节模糊），不如准备几张可平铺（Tiling）的小纹理（草、岩石、泥土），然后用一张“控制图（Control Map）”来决定在哪个位置显示哪张纹理。**

作为 Unity 开发者，你肯定见过 Terrain 系统里的 Paint Texture 工具，你在刷地表的那个过程，本质上就是在画 Splatmap。

以下是 Texture Splatting 的技术全解，从原理到现代 3A 级的高级应用。

---

### 1. 核心原理：Splatmap (Control Map)

Texture Splatting 的灵魂在于一张或多张被称为 **Splatmap**（也叫 Alpha Map 或 Weight Map）的特殊纹理。

*   **数据结构：** 通常是一张 **RGBA 格式** 的纹理。
*   **含义：**
    *   **R 通道 (Red):** 对应 Layer 1（比如草地）的权重。
    *   **G 通道 (Green):** 对应 Layer 2（比如泥土）的权重。
    *   **B 通道 (Blue):** 对应 Layer 3（比如岩石）的权重。
    *   **A 通道 (Alpha):** 对应 Layer 4（比如沙子）的权重。

#### 混合公式 (Shader 逻辑)
在 Fragment Shader 中，对于地形上的每一个像素，计算过程如下（伪代码）：

```glsl
// 1. 采样控制图
float4 splatControl = tex2D(SplatMap, uv_control);

// 2. 采样各层物理材质 (Albedo)
float3 colLayer1 = tex2D(GrassTex, uv_world * tileScale1).rgb;
float3 colLayer2 = tex2D(DirtTex,  uv_world * tileScale2).rgb;
float3 colLayer3 = tex2D(RockTex,  uv_world * tileScale3).rgb;
float3 colLayer4 = tex2D(SandTex,  uv_world * tileScale4).rgb;

// 3. 线性混合 (Linear Blending)
float3 finalColor = (colLayer1 * splatControl.r) + 
                    (colLayer2 * splatControl.g) + 
                    (colLayer3 * splatControl.b) + 
                    (colLayer4 * splatControl.a); // 假设 sum(rgba) == 1.0
```

### 2. 进阶痛点：线性混合太丑了 (Linear Blending Problem)

上面那种基础算法有一个巨大的视觉缺陷：**“幽灵般的过渡”**。
当你把石头（Rock）和沙子（Sand）混合时，如果权重各是 0.5，你会看到一个半透明的石头叠在半透明的沙子上，看起来像**模糊的烂泥**，非常不真实。

现实世界是：**沙子会填满石头的缝隙，直到盖过石头。** 要么是石头，要么是沙子，它们通常有明确的物理边界，而不是半透明叠加。

#### 解决方案：基于高度的混合 (Height-Based Blending)

这是现代游戏（包括 Unity 的 HDRP/URP 地形 Shader）的标准做法。

1.  **准备数据：** 给每个 Layer 的纹理加一个 **高度图（Height Map）**（通常塞在 Albedo 的 Alpha 通道或者单独的 Mask Map 里）。
    *   草地的高度均一。
    *   鹅卵石的高度图：石头部分是白色（高），缝隙是黑色（低）。
2.  **混合逻辑：**
    在 Shader 里比较两个 Layer 的高度。只有当 **(层A的高度 + 权重A) > (层B的高度 + 权重B)** 时，才显示层A。

**视觉效果：**
沙子会优先填入鹅卵石本身高度较低的缝隙里。随着沙子权重增加，它会像水一样漫过石头，而不是把石头变透明。这能产生极度真实的细碎几何感。

### 3. 性能瓶颈与优化：Texture Arrays

在以前（比如 Unity 5 时代），一张 Splatmap 最多支持 4 层纹理。如果你想用 8 层纹理怎么办？
*   **老办法：** 多 Pass 渲染（Multi-Pass）。画一遍地形（4层），开启 `Blend One One`，再画一遍地形（另外4层）。
    *   *缺点：* Draw Call 翻倍，性能血崩。

**现代做法：Texture Arrays (纹理数组)**
DX10/11 引入了 `Texture2DArray`。
*   我们把游戏里所有的地形贴图（比如 16 层：草、岩、泥、雪...）全部塞进**一个**纹理数组对象里。
*   **Shader 采样：** `TextureArray.Sample(uv, index)`。
*   **优势：**
    *   只需要 **1 个 Draw Call** 就可以渲染理论上无限层（取决于显存）。
    *   Splatmap 的每个通道不再直接存权重，而是存 **索引(Index)** 和 **权重(Weight)** 的组合。

---

### 4. 终极形态：Virtual Texturing (虚拟纹理 / RVT)

Texture Splatting 最大的问题是**“昂贵的 Shader 计算”**。
想象一下，如果你的地形特别复杂，用了 8 层混合，还要算 Normal、Roughness、AO、Height Blend。显卡每个像素要采样 8x3=24 次纹理，ALU 计算量巨大。

**Runtime Virtual Texturing (RVT)** 彻底终结了这个问题：

1.  **原理：**
    既然地形是静态的（大部分时候），为什么我不把混合好的结果（Splatting 之后的样子）拍一张照片存起来？
2.  **流程：**
    *   有一个专门的低开销 Pass，预先计算好地形的 Splatting 结果。
    *   把结果写入一张巨大的缓存纹理（Virtual Texture Cache）。
    *   **主相机渲染地形时：** **不再进行 Splatting 计算！** 直接采样这张已经混合好的缓存纹理。
3.  **结果：**
    无论你用了 4 层还是 40 层混合，对于最终渲染来说，消耗都是 **1 次纹理采样**。性能与层数无关。

---

### 5. 常见问题：Tiling 重复感 (Tiling Artifacts)

因为 Splatting 用的基础纹理（如草地）通常只有 1m x 1m 或 2m x 2m，在大片平原上平铺时，会出现极其难看的网格状重复图案。

解决这个问题的“三板斧”：

1.  **Macro Global Map (宏观贴图)：**
    叠加一层覆盖整个地形的超低频噪点图，打破纯色感。
2.  **Distance Tiling (距离平铺)：**
    *   近处：UV Scale = 1（显示细节）。
    *   远处：UV Scale = 0.1（混合成大块颜色，去除高频噪点）。
3.  **Stochastic Texturing (随机纹理/六边形采样)：**
    这是高级 Shader 技术。在采样纹理时，不使用标准的网格 UV，而是根据噪点旋转 UV、或者打乱 UV 的区块，从数学上消除周期性重复。Unity 的一些高级 Shader 包（如 MicroSplat）就内置了这个功能。

### 总结

*   **Splatting** 就是用蒙版（Mask）来混合多层材质。
*   **Linear Blend** 是过去式，现在主流是 **Height Blend**（产生物理堆积感）。
*   **Texture Arrays** 解决了层数限制。
*   **RVT (Virtual Texturing)** 解决了层数过多导致的性能问题。
*   它是地形系统“表皮”之所以看起来像地球而不是像 3D 模型的根本原因。
