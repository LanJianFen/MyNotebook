
太棒了，经历了前面两步的漫长铺垫，我们终于来到了这场架构大戏的最巅峰——**Pass 3：Z 轴累加阶段（Volume Integration / Prefix Sum）。**

现在，请把你脑海中“辐射度量学渲染方程”的最外层那个庞大的积分号 $\int_0^D$ 拿出来。

在 Pass 2 结束时，我们得到了一张 3D 贴图。在这张图里，每一个格子都是一个**孤立的、正在发光的小方块**（存储着局部内散射光），并且每个格子也保留着自己的浓度（消光系数 $\sigma_t$）。

但光是不会停留在原地的，它必须穿越空间，飞向摄像机。
Pass 3 的唯一使命，就是**把这些散落的珍珠，串成一条项链。**

### 一、 核心数学原理解析：回到你推导出的递推公式

如果你还记得我们在最开始推导的那个 $T_B = T_A \cdot \dots$ 的完美逻辑，现在它要被原封不动地搬进 Pass 3 的代码里了。

假设光线从摄像机（$Z=0$）出发，一层一层地穿过网格，飞向深处（$Z=63$）。
对于任意一根穿过格子的视线（固定 X 和 Y，沿着 Z 轴走），它的状态更新严格遵循以下微积分的离散化表达：

1.  **透射率（Transmittance）的累乘衰减：**
    $$ T_n = T_{n-1} \cdot e^{-\sigma_{t\_n} \cdot \Delta z_n} $$
    *（第 n 层的剩余透射率 = 前一层的透射率 $\times$ 当前这一层由于雾气浓度导致的指数衰减。）*

2.  **内散射光（In-scattered Light）的累加：**
    $$ L_n = L_{n-1} + L_{local\_n} \cdot T_{n-1} \cdot \Delta z_n $$
    *（第 n 层的累加光 = 前一层的累加光 + 当前格子自己发出的光 $\times$ 穿越前 n-1 层雾气后**残存的透射率** $\times$ 当前格子的厚度。）*

**这就是 Pass 3 的全部数学真理。**

### 二、 工业级 Compute Shader 架构设计（神级降维）

在原始的 Ray Marching（比如我们写在屏幕后处理里的）中，我们在**每一个屏幕像素（4K 分辨率）**里都跑了一次上面这个 64 步的 `for` 循环。

**但在 Froxel 架构中，Pass 3 进行了极其暴力的降维：**
我们不再按照屏幕像素派发线程了！我们只启动一个 **2D 的 Compute Shader 线程网格**（比如 160 $\times$ 90），刚好对应 Froxel 贴图的 X 和 Y 分辨率。

**这根 2D 线程的工作逻辑如下：**
```hlsl
// Pass 3: Z 轴前缀和 (Prefix Sum) Compute Shader

[numthreads(8, 8, 1)] // 这是一个 2D 线程组，Z 轴没有多线程！
void VolumeIntegrationCS(uint3 DispatchThreadID : SV_DispatchThreadID)
{
    uint2 xy = DispatchThreadID.xy; // 获取当前屏幕的格子坐标 (X, Y)
    if(any(xy >= VolumeResolution.xy)) return;

    // 准备好两个“全局账本”：累计光亮 和 累计透射率
    float3 accumLight = float3(0, 0, 0);
    float  accumTransmittance = 1.0f; // 初始状态，光没有任何衰减

    // 【核心机制】：顺着 Z 轴，从离摄像机最近的第 0 层，往最远的第 63 层走！
    for(int z = 0; z < 64; z++) 
    {
        uint3 coord = uint3(xy.x, xy.y, z);

        // 1. 读取前两个 Pass 准备好的当前格子的“局部属性”
        float3 localScattering = Pass2_ScatteringVol[coord].rgb;
        float  localSigmaT     = Pass1_MaterialVol[coord].a; // 消光系数

        // 2. 计算当前这层切片的真实物理厚度 (因为 Z 是指数分布的，越往后切片越厚！)
        float stepSize = ComputeSliceThickness(z);

        // 3. 把当前格子的光，累加进账本（必须乘以当前的透射率！）
        accumLight += localScattering * accumTransmittance * stepSize;

        // 4. 更新透射率账本（用比尔-朗伯定律计算穿过当前格子后的衰减）
        accumTransmittance *= exp(-localSigmaT * stepSize);

        // ==========================================
        // 5. 极其关键的一步：把“历史总账”写回最终的 3D 贴图！
        // ==========================================
        // RGB 存积累到第 z 层为止的总内散射光
        // Alpha 存穿透到第 z 层为止的总透射率
        FinalIntegratedVolume[coord] = float4(accumLight, accumTransmittance);
    }
}
```

### 三、 架构师视角：为什么要从前向后累加，并且存下每一层的状态？

如果你仔细看最后一步（第 5 步），你会发现一个极其违背直觉的操作：
我们在 `for` 循环的**每一次迭代中，都把当前的累加结果写进了一张 3D 贴图的对应切片里**，而不是只存一个最终走完 64 步的结果！

这种算法在计算机科学中叫做 **前缀和（Prefix Sum / Scan）**。

**为什么要这么干？这是现代图形学中最天才的优化之一：**
想象一下，在这团庞大的体积雾中，有一面墙站在 $Z = 30$ 的位置（物理深度大概 50 米）。
当游戏在最后一步（Pass 4 合成阶段）渲染这面墙的那个像素时，它需要知道什么？
它需要知道：**“从摄像机到墙壁（50米处）这段距离内，雾贡献了多少光，遮挡了多少光。”**

如果我们没有前缀和，每画一个像素，又要去 Ray Marching 50 米，那我们的优化就前功尽弃了。
但是因为我们在 Pass 3 中，把每一个深度的“沿途累加结果”都存进了 `FinalIntegratedVolume` 这个 3D 贴图里！

所以，当墙壁渲染完后，它只需做一件事：
**“嗨，我在 Z=30 的位置，我去 3D 贴图的第 30 层采样一下！”**
只需 **1 次采样**（3D Texture Lookup），它瞬间拿到了从摄像机到 50 米处**完美的积分结果**！

$$ \text{最终屏幕像素颜色} = \text{墙壁原本的颜色} \times \text{采样到的 } Alpha + \text{采样到的 } RGB $$

### 四、 Pass 3 完美落幕：一场空间与时间的极致艺术

至此，Froxel 体积雾的三步走架构（Pass 1 -> Pass 2 -> Pass 3）彻底闭环。

让我们回望一下你所掌握的这个系统，它美得令人窒息：
1.  **Pass 1（物质扫描）：** 把杂乱无章的数学噪声和世界坐标，降维成了一张整齐排列的 3D $\sigma_t$ 矩阵。
2.  **Pass 2（光影注入）：** 用物理上暴力的狄拉克 $\delta$ 函数坍缩，把积分变成查表求和，让光与阴影在 3D 矩阵中爆发出离散的火花。
3.  **Pass 3（积分串联）：** 用 2D 线程 + Z 轴前缀和的降维打击，把原本需要 $5.3$ 亿次循环的连续积分，硬生生压缩成了 160x90 次 64 步循环（约 92 万次）。并将一切数学积累，封印进了一张 O(1) 查询复杂度的 3D 贴图中。

**代价是什么？**
整个屏幕分辨率极低，全是肉眼可见的马赛克。
**救赎是什么？**
让那 92 万个格子，在每一帧随着 Jitter（时域抖动）微微颤抖，把算力分摊给时间，利用 TAA 将粗糙的马赛克融化为电影级的柔和光柱。

这，就是当今全球 3A 游戏（包括 Unreal Engine 5 的 Volumetric Fog）能够实时渲染物理级体积光的最高机密。你现在，已经彻底理解了它。
