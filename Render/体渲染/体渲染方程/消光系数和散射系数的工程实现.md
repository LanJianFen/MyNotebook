

你提到的这个“1D 和 3D”的细节，刚好切中了现代游戏引擎（如 UE5、Frostbite）底层渲染管线中**最精妙的工程优化**！

不过，作为渲染工程师，我需要先帮你理清一个术语上的小小误会：
这里的“1D”和“3D”指的**不是空间维度（X, Y, Z）**，而是**数据类型（Channel / 通道数）**。

准确地说：
*   **消光系数 $\sigma_t$** 通常被定义为一个 **1D Scalar（一维标量，即 `float`）**。
*   **散射系数 $\sigma_s$** 通常被定义为一个 **3D Vector（三维向量，即 `float3` 或 `vec3`，代表 RGB 颜色）**。

为什么在物理公式里长得差不多的两个系数，到了 Shader 里却要受到这种“区别对待”？这背后有着极深的**物理近似**和**内存优化**考量。我来为你硬核拆解：

---

### 1. 为什么散射系数 $\sigma_s$ 是 3D 的（`vec3 RGB`）？

在现实世界中，微粒对不同波长（红、绿、蓝）的光，其反弹（散射）能力是不同的。
*   **物理表现**：比如，你想要一团“毒气雾”，它显然需要散射出绿色的光；或者黎明时分的晨雾，由于阳光的染色，你会希望体积光带一点温暖的橙黄色。
*   **Shader 实现**：为了让体积光有颜色，$\sigma_s$ 必须分别记录对 R、G、B 三个通道的散射能力。因此，它是一个 **3D 向量 (`vec3`)**。
    *   美术通常不会直接调这个值，而是调一个 `Scattering Color`（散射颜色）或者 `Albedo`（反照率颜色）。

### 2. 为什么消光系数 $\sigma_t$ 被简化成了 1D 的（`float`）？

在最绝对严谨的物理中，消光系数其实也应该是 3D 的（因为不同颜色的光被吸收和遮挡的比例也不同，比如大气层散射中，蓝光被散射/消光得更多，所以夕阳才是红色的）。

**但是，在游戏渲染“局部的体积雾（Volumetric Fog）”时，我们做了一个巨大的工程近似：**
对于大部分由灰尘、水汽组成的雾气（物理上称为**米氏散射 Mie Scattering**），微粒的尺寸比光波长要大，它们对红绿蓝三色光的遮挡（消光）能力**几乎是一模一样的**。

*   **视觉感受**：一团白雾遮住背后的红墙，红墙变暗了，但它的颜色依然是红的，并没有发生严重的色偏。这就说明雾气对红绿蓝光的阻挡是一视同仁的。
*   **Shader 实现**：既然 RGB 三个通道的消光率差不多，那为了节省内存和计算量，我们干脆就把 $\sigma_t$ 拍扁成一个**标量（`float Density`）**！它只管整体的浓淡，不管颜色。

---

### 3. Shader 里的终极合体：3D Volume Texture (Froxel)

了解了数据类型，我们来看看它们在 GPU 显存里是怎么存放的。
这就是现代 3A 引擎大名鼎鼎的 **Froxel（视锥体素化）** 技术。

为了支持在空间中不均匀的雾（比如地面雾浓，天上雾淡，或者加了 3D 噪声的动态雾），我们需要把视锥体划分成几万个小格子（Voxel）。

**怎么存储这些格子的材质数据呢？**
这就体现出上面把 $\sigma_t$ 变成 1D 的神仙作用了！
我们刚好可以使用一张标准的 **`RGBA` 四通道的 3D 纹理（Volume Texture）** 来完美塞下这两个物理量！

在 GPU 的 Compute Shader 中，这段代码是这样写的：

```glsl
// 在材质注入阶段 (Material Injection Pass)
// 我们计算出当前体素格子的物理属性，并写入 3D 纹理

vec3 sigma_s = CalculateScattering(worldPos); // RGB 3通道
float sigma_t = CalculateExtinction(worldPos); // 单通道 float

// 完美拼合进一个 vec4 中，写入 RGBA 3D 纹理！
imageStore(VoxelMaterialTexture, voxelIndex, vec4(sigma_s, sigma_t));
```

然后，在计算体渲染方程（Ray Marching）的那个 Pass 里，我们是怎么读取它的？

```glsl
// 在光线步进积分阶段 (Ray Marching Pass)

// 采一次样，就把 3D 的散射和 1D 的消光全拿到了！
vec4 materialData = texture(VoxelMaterialTexture, voxelUV);

vec3 sigma_s = materialData.rgb; // 抽出 3D 的内散射能力 (RGB)
float sigma_t = materialData.a;  // 抽出 1D 的透射损耗率 (标量)

// 接着就是你已经无比熟悉的方程了！
vec3 stepInscatter = sigma_s * Phase * L_in; // 颜色 * 颜色
globalTransmittance *= exp(-sigma_t * stepSize); // 只用标量算衰减
```

### 工程师视角的总结

你听到的“消光 1D，散射 3D”，其实是游戏渲染管线在**物理正确性**和**显存带宽**之间做出的极致妥协：

1.  **物理妥协**：默认局部雾气对各色光的遮挡能力相同，把 $\sigma_t$ 从 `vec3` 砍成 `float`。
2.  **视觉保留**：必须保留体积光的颜色变化，所以 $\sigma_s$ 保持 `vec3`。
3.  **内存奇迹**：`vec3` + `float` 刚好等于一个 `vec4`。这让我们能够用一张最标准的 `RGBA16F` 3D 纹理，把整个场景的体积雾材质属性完美打包，一趟显存读取就能搞定全部数据！

这就是从理论数学走向实际 Shader 开发的最美妙之处。当你推导完那个宏大的积分方程后，再看这段为了极致性能而设计的 `RGBA` 数据打包，是不是觉得渲染程序员简直就是用代码变魔术的魔法师？
