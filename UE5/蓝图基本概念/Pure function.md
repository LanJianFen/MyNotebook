

在蓝图中，当你把一个 Function 设置为 **Pure**（纯函数）后，它的外观和行为会发生巨大变化。

### 1. 外观区别
*   **普通函数 (Impure)**：有白色的**执行引脚 (Exec Pins)**。
    *   也就是那个白色的小箭头 `▶`。你必须把白线连进去，它才会运行。
*   **纯函数 (Pure)**：**没有执行引脚**。
    *   它就像是一个数据节点（绿色的 `+` 号、`Get Actor Location` 都是典型的纯函数）。它只有数据输入和数据输出。

### 2. 行为核心：只有在“被需要”时才运行
*   **普通函数**：**手动触发**。白线流到它，它就跑一次，不多不少。结果会被存在输出引脚上供后面使用。
*   **纯函数**：**被动触发**。
    *   它不会自己跑。
    *   **每次**当别的节点读取它的**输出引脚**时，它都会**重新运行一遍**。

---

### ⚠️ 纯函数最大的“坑” (这也是面试常考题)

假设你写了一个 Pure Function 叫 `GetRandomNumber`（获取随机数），里面放了一个 `Random Int` 节点。

**你的连线是这样的**：
`GetRandomNumber` 的输出引脚，分叉连给了两个 `Print String`。
1.  Print A
2.  Print B

**结果**：
*   A 打印了 "5"。
*   B 打印了 "8"。
*   **它们不一样！**

**为什么？**
因为它没有缓存结果。
*   当 Print A 需要数据时，`GetRandomNumber` 跑了一次，算出了 5。
*   当 Print B 需要数据时，`GetRandomNumber` **又跑了一次**，这次算出了 8。

**如果是普通函数 (Impure)**：
*   白线流过它，算出 5。
*   Print A 拿到 5。
*   Print B 拿到的还是刚才算出来的那个 5。

---

### 什么时候用 Pure Function？

**黄金法则：**
只有当函数的结果**仅仅依赖于输入参数**，且**没有任何副作用（Side Effects）**时，才使用 Pure。

*   **适合 Pure 的场景**：
    *   数学运算：`1 + 1` 永远等于 2，不用担心它跑两次结果不一样。
    *   读取数据 (Getter)：`Get Health`，`Get Actor Location`。
    *   类型转换：`Vector to Transform`。

*   **绝对禁止用 Pure 的场景**：
    *   **随机数生成**（就像上面的例子）。
    *   **生成物体**（Spawn Actor）：否则你每连一次线，它就多生一个怪。
    *   **修改变量**（Set Variable）：不要在 Pure 函数里改数值，否则你都不知道它到底被改了几次。

**一句话总结**：
Pure 函数就是蓝图里的**计算器**——不算完不给数，要用数再才算。
