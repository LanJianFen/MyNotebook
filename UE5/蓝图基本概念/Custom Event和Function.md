

这是所有 UE 开发者都会经历的困惑。**Function (函数)** 和 **Custom Event (自定义事件)** 在 80% 的情况下确实能实现同样的效果（比如把一段逻辑封装起来），但剩下的 20% 决定了它们的**本质区别**。

### 1. 最大的区别：Latent Action (潜伏/延时操作) ⏳
这是决定性的一点。

*   **Custom Event**：**支持延时节点**。
    *   你可以在事件里放 **`Delay` (延迟)**、**`Timeline` (时间轴)**、**`Retriggerable Delay`**。
    *   *场景*：比如“开门”逻辑，你要先播动画，Delay 2秒，再关门。这必须用 Custom Event。
*   **Function**：**不支持延时节点**。
    *   函数要求“立刻执行，立刻返回”。你不能在函数里让线程“等一会儿”。函数里甚至连 Timeline 组件都加不进去。
    *   *场景*：计算伤害公式、根据 ID 查名字。这种“算完立马给结果”的逻辑适合函数。

### 2. 返回值 (Return Values) ↩️
*   **Function**：有原生的**返回值 (Return Node)**。
    *   调用函数时，节点右边直接有输出引脚，拿到计算结果，非常顺手。
*   **Custom Event**：**没有返回值**。
    *   事件是“发射后不管 (Fire and Forget)”的。虽然你可以通过修改引用参数来模拟返回值，但很不直观，也不能作为纯函数（Pure Function）使用。

### 3. 网络复制 (Replication / RPC) 🌐
如果你做多人游戏，这一点至关重要。

*   **Custom Event**：**支持网络复制**。
    *   你可以在 Details 面板里把事件设为 `Run on Server`（在服务器跑）或 `Multicast`（全广播）。这是写联机逻辑的核心。
*   **Function**：**不支持直接复制**。
    *   函数只能在被调用的那台机器上跑（除非它被包含在一个复制的事件里）。

### 4. 纯函数 (Pure Function) 🧪
*   **Function**：可以设为 **Pure**（在 Details 里勾选）。
    *   Pure 函数没有执行引脚（白色箭头），只要你需要数据它就会算一次。非常适合数学计算或Getter（例如 `GetHealth`）。
*   **Custom Event**：不能做成 Pure 的。

---

### 总结：我该用哪个？

| 需求 | 选哪个？ |
| :--- | :--- |
| **需要 Delay、时间轴、等待** | 必须用 **Custom Event** |
| **需要有返回值（算出结果给别人用）** | 必须用 **Function** |
| **需要多人联机（RPC）** | 必须用 **Custom Event** |
| **只是为了整理代码（封装逻辑）** | 两个都行，但推荐 **Function** (更整洁，可放入局部变量) |
| **需要作为接口 (Interface) 实现** | 如果接口没返回值 -> Event<br>如果接口有返回值 -> Function |

**老鸟的习惯**：
*   **动作类**（开门、生成特效、重生）：用 **Custom Event**。
*   **数据类**（算血量、检查距离、获取状态）：用 **Function**。
