别担心，这绝对是 Unity 动画系统里最绕人的地方。十个初学者里有九个会在这里卡住。你的疑惑非常精准，我们就针对你提的这四个问题，一个一个“掰碎了”来解答！

为了方便理解，请先记住**一个核心比喻**：
*   **GameObject 的 Transform** = **“传送带”**（代表在游戏世界里的真实坐标）。
*   **角色的骨骼（姿势 Pose）** = **“演员”**（站在传送带上表演的人）。
*   **Root Q 和 Root T** = **用来控制“传送带”移动和旋转的遥控器数据**。

---

### 问题 1：当我没勾选 Bake into pose 的时候，Unity 会为我自动计算 Root Q 和 Root T 吗？
**答：是的，百分之百会自动计算！**

当你不勾选 `Bake Into Pose` 时，你其实在告诉 Unity：“**请提取动画里的位移，用来驱动传送带（GameObject）！**”
于是，Unity 会非常聪明地分析原始 FBX 里的动作，把向前跑的那 3 米的位移数据**抽离**出来，自动帮你填入 `Root T`（平移）曲线中。
此时，“演员”在传送带上是原地跑的，但由于 `Root T` 有了数据，它会驱动“传送带”往前走 3 米。最终表现出的结果是：角色在游戏世界里往前跑了 3 米。

---

### 问题 2：当我勾选了 Bake into pose，意味着我不想动画影响 GameObject 的 transform 了吗？
**答：完全正确！你理解得很透彻。**

当你勾选 `Bake Into Pose` 时，你是在告诉 Unity：“**把所有的位移都‘烘焙（Bake）’死在‘演员（姿势）’身上，千万别动我的传送带（GameObject）！**”
此时，位移完全由角色的骨骼（比如 Bip001）来表现，角色视觉上跑了 3 米，但 GameObject 的实际 Transform 坐标一直停留在 `(0,0,0)`。由于 GameObject 不动了，所以如果要在游戏里让角色真正位移，就必须靠你自己写 C# 代码（比如给刚体施加力）去移动它。

---

### 问题 3：当我勾选了 Bake into pose，我应该自己去调整 Root T 和 Root Q 吗？
**答：不需要，也千万别去调。**

因为当你勾选 `Bake Into Pose` 时，Unity 已经明白你不想让传送带（GameObject）移动了。所以，Unity 会**自动把 Root T 和 Root Q 的数据清零（变成一条死寂的直线）**。
既然你的目的就是让 GameObject 的坐标不被动画干扰，那这两条线保持为 0 就是最完美的。你不需要管它们。

---

### 问题 4：当我没勾选 Bake into pose 时，我自己调整 Root Q 和 Root T 有什么作用？
**答：用来强行修改或微调角色 GameObject 在游戏里的“实际移动轨迹”。**

假设美术给你做了一个“前滚翻”的动作（没勾选 Bake），Unity 自动计算出 `Root T` 的 Z 轴向前移动了 **2 米**。
但游戏策划测试后说：“这个技能位移太短了，让角色滚出 **4 米** 吧！”

这时候你有两个选择：
1.  **让美术重新做**（麻烦，费时间）。
2.  **你在 Unity 里手动修改 Root T**：你把动画提取成独立的 `.anim`，然后打开动画曲线，强行把 `Root T` 的 Z 轴终点从 2 提升到 **4**。
    *   **作用/结果**：当播放这段动画时，角色依然播放着以前那个翻滚动作，但是**“传送带”的速度变快了**，带着角色往前冲了 4 米。
    *   *（注：修改过大可能会导致角色看起来像在“滑冰”，但这作为小幅度的微调极其有效。）*

| 操作状态 | 核心含义 | Root T 和 Q 的状态 | GameObject (Transform) 会怎样？ | 骨骼姿势 (Pose) 会怎样？ |
