

你观察得极其敏锐！这是一个非常经典的图形学“错觉”，几乎所有初学 Shader 的人都会在这个地方产生同样的疑问。

核心答案是：**“正常的遮挡关系” 和 “生成 `_CameraDepthTexture`” 完全是两码事！它们用的是两个不同层面的“深度”。**

产生正常遮挡，**根本不需要 `DepthOnly` Pass！**

为了解开这个谜团，我们要区分两个概念：**硬件 Z-Buffer（深度缓冲区）** 和 **软件全局贴图 `_CameraDepthTexture`**。

---

### 1. 为什么遮挡关系是正常的？（硬件 Z-Buffer 的功劳）

当你写了一个自定义 Shader，里面只有绘制颜色的主 Pass（例如 `LightMode = UniversalForward`，或者什么都不写）。

渲染这个物体时，管线的实际操作是这样的：
1.  GPU 开始跑你的主 Pass。
2.  像素算出颜色。
3.  **注意！** 只要你的 Shader 没有写 `ZWrite Off`（默认是 `ZWrite On` 开启的），GPU 在把你的颜色画到屏幕（Color Buffer）上的**同时**，会自动把这个像素的深度距离，写入到底层显卡的 **硬件 Z-Buffer（深度缓冲区）** 中。
4.  当下一个物体要画的时候，GPU 会自动拿新物体的深度和这个 **硬件 Z-Buffer** 做对比（ZTest）。

**结论：** 正常的远近遮挡，是 GPU 硬件底层自带的保底机制。它发生在**画彩色的主 Pass 执行期间**，不需要专门找个 Pass 去跑。

---

### 2. 那 `DepthOnly` Pass 到底是干嘛用的？

既然画彩色的时候已经顺手做了深度测试，为什么还要专门写一个毫无颜色的 `DepthOnly` Pass 呢？

想象一个场景：
你的游戏里有一片半透明的海水。海水的 Shader 需要读取整个世界的深度图（`_CameraDepthTexture`），来计算“海水插在了海岸的哪里”，从而画出白色的浪花。

**矛盾来了：**
*   半透明的海水必须在**所有不透明物体（比如石头、海岸）画完之后**才能画。
*   如果在画海水的刚好那一刻，海岸的深度数据还没准备好给海水读取怎么办？

这时候，Unity 管线会做一件事，叫作 **深度预渲染（Depth Prepass）**：
1. 在真正画所有物体的彩色画面**之前**。
2. 管线大喊一声：“所有带 `DepthOnly` 标签的 Pass 出列！”
3. 哗啦啦，所有物体用极低的性能把自己的形状“提前”画了一遍黑白图。**这张图，就是 `_CameraDepthTexture`。**
4. 然后再开始正常画所有物体的彩色画面（`UniversalForward`）。
5. 最后画半透明海水。海水开心地拿到了第 3 步生成的 `_CameraDepthTexture`，完美算出了浪花。

**如果你自定义的石头 Shader 没有写 `DepthOnly` Pass 会怎样？**
*   **遮挡正常**：石头和主角的遮挡依然完美（因为靠的是彩色阶段的硬件 Z-Buffer）。
*   **特效变成幽灵**：因为在第 3 步点名时石头没出列，`_CameraDepthTexture` 里**根本没有这块石头**。当海水跑去读取贴图时，会认为那里空无一物。结果就是：**海水会直接穿透这块石头，没有浪花，没有水深颜色变化，石头在深度检测类特效面前变成了“幽灵”！**

---

### 3. 终极反转：为什么有时候没写，深度贴图特效依然正常？

如果你发现自己没写 `DepthOnly`，但海水的浪花依然正常作用于你的物体了，那是因为遇到了以下两种情况之一：

#### 情况 A：URP 管线的“神级优化”（Copy Depth）
URP 管线极其聪明。它发现如果要让所有模型都多跑一次 `DepthOnly` Pass 太耗性能了。
如果在 URP 设置里没有强制开启 Depth Prepass，管线的流程会变成这样：
1. 正常画所有不透明物体的彩色（跑主 Pass）。在这个过程中，GPU 硬件底层已经生成了天然的 **硬件 Z-Buffer**（用来做遮挡）。
2. 在画半透明海水之前，URP 管线执行一个神级操作：**直接把显卡底层的 硬件 Z-Buffer “咔嚓”截个图（Copy Depth），把这张截图硬生生命名为 `_CameraDepthTexture`**！
3. 海水读取这张截图，一切正常。

在这种模式下，**你确实不需要写 `DepthOnly` Pass**，你的物体依然能神奇地出现在 `_CameraDepthTexture` 里！

#### 情况 B：你偷偷借用了别人的 Pass（Fallback）
如果你在 Shader 的最下面写了这一句：
`Fallback "Diffuse"` 或者 `Fallback "Universal Render Pipeline/Lit"`
当管线大喊“带 `DepthOnly` 的出列”时，你的 Shader 本身没有，但引擎会偷偷跑去 `Fallback` 指定的代码里，把标准材质的 `DepthOnly` 借过来跑一遍。这也是初学者经常意识不到的事情。

### 总结
1. **看遮挡**：看主 Pass 里的 `ZWrite` 和 `ZTest`，不管有没有深度贴图，它都不会错。
2. **看深度贴图特效**（景深、雾效、水面、软粒子）：取决于 URP 的管线配置（是跑 Prepass 还是 Copy Z-buffer），如果跑 Prepass，没写 `DepthOnly` 的物体就是特效眼中的**透明幽灵**。
