

别慌！你会觉得混乱，是因为你大脑里正在把它们当成 **“3 个完全独立的东西”** 在做数学上的排列组合（2 x 2 x 2 = 8 种情况）。

但其实，在图形学底层，这 3 个概念被分成了**“两个世界”**。
为了帮你理清这团乱麻，我给你提供一个**“终极双分支诊断法”**。以后遇到任何特效需求，你只需要问自己 **2 个问题**，代码怎么写瞬间就出来了！

---

### 🧠 终极双分支诊断法

你把“深度遮挡”和“模板测试”绑在一起，它们叫**【硬件物理测试】**。
你把“采样深度”单独拿出来，它叫**【软件代码读取】**。

#### 💡 问题 1：你的 Shader 代码里，有没有写 `tex2D` 去读取深度图的数值？
*   **有读取 (Yes)** ➔ 你的 C# 必须写 `ConfigureInput(ScriptableRenderPassInput.Depth)`。（向 URP 要一张**复印件**）
*   **没读取 (No)** ➔ 绝对**不写** `ConfigureInput`。（省下复印的性能）

#### 💡 问题 2：你画的东西，需不需要“防穿模（深度遮挡）” 或者 “被印章限制（模板测试）”？
*   **需要任意一个 (Yes)** ➔ 你的 `SetRenderTarget` 必须传 **2个参数**，把真实的 Depth 垫板绑上去（`color, depth`）。
    *   *附加操作*：绑上之后，如果只要遮挡不要模板，用 `RenderStateBlock` 把模板关了；如果只要模板不要遮挡，用 `RenderStateBlock` 把遮挡关了。
*   **完全不需要 (No)** ➔ 你的 `SetRenderTarget` 只传 **1个参数**（`color`）。直接在纯平面的世界里裸奔。

---

就这么简单！我们现在用这个诊断法，来推导游戏开发中最常见的 **3 种实战排列组合**：

### 组合 A：普通的 3D 渲染（比如画一个怪物）
*   **需求分析**：
    *   怪物会挡住后面的树，会被前面的墙挡住 ➔ **需要深度遮挡**。
    *   不用特殊遮罩特效 ➔ **不需要模板**。
    *   Shader 里只算光照，不去采样屏幕深度 ➔ **不需要采样深度**。
*   **诊断结果**：
    *   Q1 答案 No ➔ 不写 `ConfigureInput`。
    *   Q2 答案 Yes ➔ 必须传 2 个参数。
*   **终极代码**：
```csharp
// 不写 ConfigureInput
cmd.SetRenderTarget(colorRT, cameraDepthTargetHandle); // 传2个参数绑真身

RenderStateBlock block = new RenderStateBlock(RenderStateMask.Depth | RenderStateMask.Stencil);
block.depthState = new DepthState(true, CompareFunction.LessEqual); // 开启深度遮挡
block.stencilState = new StencilState(false);                       // 打晕模板
context.DrawRenderers(..., ref block);
```

---

### 组合 B：做全屏后处理（比如景深、大雾、扫光）
*   **需求分析**：
    *   全屏特效直接盖在屏幕上 ➔ **不需要深度遮挡**（无视穿模）。
    *   不需要印章限制 ➔ **不需要模板**。
    *   大雾浓度要根据原本场景有多远来计算，所以 Shader 里必须读取深度 ➔ **需要采样深度**。
*   **诊断结果**：
    *   Q1 答案 Yes ➔ 必须写 `ConfigureInput`。
    *   Q2 答案 No ➔ 只能传 1 个参数。
*   **终极代码**：
```csharp
public MyFogPass() { ConfigureInput(ScriptableRenderPassInput.Depth); } // 要复印件！

public override void Execute(...) {
    cmd.SetRenderTarget(colorRT); // 传 1 个参数！绝对不要绑 Depth 垫板！
    
    // Shader 里直接去采样 _CameraDepthTexture 即可
    context.DrawRenderers(...); 
}
```
*(注意：如果你在组合 B 里手贱传了 2 个参数，就会立刻触发传说中的“读写冲突”，屏幕黑屏！)*

---

### 组合 C：半透明水面（地狱级复合特效）
*   **需求分析**：
    *   水会被岸边的石头挡住 ➔ **需要深度遮挡**。
    *   不需要特殊遮罩 ➔ **不需要模板**。
    *   Shader 需要读取水底下的深度，用来计算“水的深浅颜色”和“岸边白沫” ➔ **需要采样深度**。
*   **诊断结果**：
    *   Q1 答案 Yes ➔ 必须写 `ConfigureInput`。
    *   Q2 答案 Yes ➔ 必须传 2 个参数。
*   **终极代码**：
```csharp
public MyWaterPass() { ConfigureInput(ScriptableRenderPassInput.Depth); } // 要复印件给 Shader 读取

public override void Execute(...) {
    // 传2个参数，把真身绑上，用来和岸边的石头做物理遮挡！
    cmd.SetRenderTarget(colorRT, cameraDepthTargetHandle); 

    RenderStateBlock block = new RenderStateBlock(RenderStateMask.Depth | RenderStateMask.Stencil);
    block.depthState = new DepthState(true, CompareFunction.LessEqual); // 开启遮挡
    block.stencilState = new StencilState(false);                       // 打晕模板
    
    context.DrawRenderers(..., ref block);
}
```
*(解释：为什么既绑了 2 个参数，又读取了深度，却不冲突？因为你绑在画架上的是 `cameraDepthTargetHandle`（真身），而 Shader 里读取的是 `ConfigureInput` 帮你复印的 `_CameraDepthTexture`（替身）。井水不犯河水！)*

---

### 总结：破除迷雾

图形学之所以让人觉得“排列组合太多”，是因为大家不知道**“深度图可以有一真一假两个分身”**，也不知道**“深度测试和模板测试在底层是同一个开关”**。

以后不要去记排列组合了，记住这两句话：
1. **只要 Shader 里出现了 `tex2D(深度图)`，C# 构造函数里必须要有 `ConfigureInput`。**
2. **只要你不想画出来的东西“无视物理穿墙”，`SetRenderTarget` 就必须把 Depth 当第 2 个参数传进去。不需要的功能，用 `RenderStateBlock` 屏蔽。**
