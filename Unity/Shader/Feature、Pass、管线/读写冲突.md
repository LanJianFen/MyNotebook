
为了让你彻底明白“读写冲突”到底是怎么触发的，我们直接把引擎底层的遮羞布掀开，看看**为什么双分支法安全**，以及**你怎么写才会导致当场死机**。

---

### 一、 揭秘：为什么双分支法（绑深度 + 采深度）很安全？

在双分支诊断法的组合 C 里，你写了这样的代码：
```csharp
// 1. C# 乞讨
ConfigureInput(ScriptableRenderPassInput.Depth);

// 2. C# 绑定
cmd.SetRenderTarget(colorRT, cameraDepthTargetHandle);

// 3. Shader 读取 _CameraDepthTexture
```

为什么这**不**触发读写冲突？
核心机密在于：**`cameraDepthTargetHandle` 和 `_CameraDepthTexture` 在物理显存上，根本就不是同一张图！！！**

当你调用 `ConfigureInput` 时，URP 大管家在后台偷偷做了一件事（CopyDepth Pass）：
1. 拿真正的深度图（`cameraDepthTargetHandle`）作为源头。
2. 申请一张全新的、一模一样大小的临时贴图（命名为 `_CameraDepthTexture`）。
3. 把真身的数据**复印**到了替身里。

所以，在你的 Pass 执行时：
*   **画架（RenderTarget）**上绑的是：`cameraDepthTargetHandle`（内存地址 A）。
*   **Shader 里读取（Sampler）**的是：`_CameraDepthTexture`（内存地址 B）。

**井水不犯河水，两个不同的内存地址，当然没有任何冲突！**

---

### 二、 作死示范：真正的读写冲突是怎么触发的？

既然懂了原理，那如果要故意触发读写冲突（制造 Bug），该怎么写呢？

**核心法则：只要你把【同一个内存地址的贴图】，既绑在画架上，又传给 Shader，GPU 就会当场暴毙！**

这里给你展示两种最经典的“作死”写法：

#### ☠️ 作死写法 1：把替身当成真身绑上画架
有些新手觉得，既然 `_CameraDepthTexture` 是全局深度图，那我是不是可以直接把它绑在画架上做物理遮挡？
```csharp
// 【致命错误】：把 _CameraDepthTexture 绑到了画架上！
cmd.SetRenderTarget(colorRT, _CameraDepthTexture);

// Shader 里又写了：tex2D(_CameraDepthTexture)
context.DrawRenderers(...);
```
**结果**：画架绑的是地址 B，Shader 读的也是地址 B！**同址读写，立刻触发冲突！**

#### ☠️ 作死写法 2：自定义临时深度的“自产自销”
假设你自己用 `GetTemporaryRT` 申请了一张叫 `m_MyCustomDepth` 的深度图。
你想在一个 Pass 里，一边根据它的深度做遮挡（比如只画在墙后面的东西），一边又要在 Shader 里读取它算特效。
```csharp
// 1. 自己造的图，地址是 C
cmd.SetRenderTarget(colorRT, m_MyCustomDepth);

// 2. 把自己造的图，当成贴图传给 Shader
cmd.SetGlobalTexture("_MyShaderTex", m_MyCustomDepth);

// 3. Shader 里写了：tex2D(_MyShaderTex)
context.DrawRenderers(...);
```
**结果**：画架绑的是地址 C，Shader 读的也是地址 C！**又触发冲突！**

### 三、 触发冲突后，底层硬件到底发生了什么？

如果你真的写出了“同址读写”的代码，不要指望 Unity 会在 Console 里温柔地给你报个红错。**因为这是一种硬件级别的未定义行为（Undefined Behavior）。**

不同的手机/电脑，死法千奇百怪：

1.  **PC 端 (DX11 / DX12)**：
    微软的驱动比较严格，它如果检测到你把一张图绑在画架上，同时又在 Shader 里去 `tex2D` 它，驱动会强行**把 Shader 里的读取结果全部变成 0（纯黑）**。你的特效瞬间消失。
2.  **苹果端 (Metal API)**：
    苹果的校验极其变态，底层直接抛出 `Resource Hazard Validation Error`，然后你的游戏可能直接**闪退**。
3.  **安卓端 (Vulkan / OpenGL ES)**：
    这是最恐怖的。因为移动端使用的是 TBR（分块渲染）架构，高速缓存正在疯狂写入数据，同时你的 Shader 又去请求读取。最后的结果是**花屏、满屏马赛克乱闪、甚至整个手机 GPU 驱动挂掉导致手机重启**。

### 工程师总结：如何避雷？

永远记住，GPU 的流水线是一个极其死板的车间：
**“贴图（Texture）在同一条流水线上，只能拥有一种身份：要么是画板（被写/被测），要么是参考书（被读）。”**

如果你真的遇到了【既想用自定义深度做物理遮挡，又想在 Shader 里读这个自定义深度】的变态需求，解决办法只有一个：
**学 URP 的做法，自己用 `cmd.CopyTexture()` 复印一份！绑真身，读替身！**
