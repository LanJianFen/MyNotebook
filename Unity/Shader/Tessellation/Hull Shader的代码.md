

你问到了**曲面细分最核心的“三大件”**！

这三个东西全部属于第一阶段——**Hull Shader（外壳着色器 / 质检经理）**的工作范畴。

在普通的 Shader 里，顶点着色器（VS）是一个点一个点处理的（互不相干）。但到了曲面细分阶段，**GPU 必须拥有“面”的概念**，否则根本不知道该怎么下刀。

我们把这三个概念用最通俗的方式拆解开：

---

### 1. `InputPatch<v2h, 3> patch` —— 什么是 Patch？（端上来的原材料）

**通俗理解：端给质检经理的一盘“完整的披萨（面片）”。**

*   **`InputPatch`**：这是 HLSL 的内置专有词汇。它告诉 GPU：“我现在拿在手里的不是一个孤立的顶点了，而是一个由几个点连赶来的**面（Patch）**”。
*   **`<v2h>`**：告诉 GPU，这个面片里的每一个点，包含什么数据？（就是我们前面定义的结构体：包含模型的三维坐标、法线、UV）。
*   **`3`**：告诉 GPU，这个面片是由 **3 个控制点（顶点）** 组成的。在图形学里，3 代表**三角形**（Triangle），如果是 4，那就代表**四边形**（Quad 控制面）。

**核心顿悟：**
在跑进 Hull Shader 之前，顶点着色器是单独运算 3 次的（算出 3 个独立的点）。到了 Hull Shader，**硬件把这 3 个点“打包合成了一个数组”**，名为 `patch`。
你想拿第一个点的 UV？写 `patch[0].uv`。想拿第三个点的位置？写 `patch[2].vertex`。你终于可以同时掌控三角形的三个角了！

---

### 2. `TessFactors` 里的参数是什么？ ——（写给切面机的“图纸”）

**通俗理解：质检经理写下的那张“切割指令单”。**

这里的参数带有 `SV_TessFactor` 等系统语义，意味着**这几个变量是显卡底层硬件（切面机）强制要求你必须填写的**，少填一个机器就不转。

如果你切的是一个三角形（控制点为 3），指令单包含两部分：
*   **`float edge[3] : SV_TessFactor;` （边缘切割数）**
    *   它代表三角形的 **3 条外边框**，每一条边要被切成几段？
    *   `edge[0]`：点 1 和 点 2 之间的边，切几刀？（比如填 4，这条边就被均匀砍成 4 段，多出 3 个新点）。
    *   `edge[1]`：点 2 和 点 0 之间的边。
    *   `edge[2]`：点 0 和 点 1 之间的边。
    *   *（高级技巧：如果你发现相邻的两个模型接缝处裂开了，通常是因为它们共享的那条边，两边的 `edge` 参数给得不一样，导致一边切了3刀，一边切了4刀，对接不上了！）*

*   **`float inside : SV_InsideTessFactor;` （内部切割数）**
    *   它代表三角形的 **正中心内部** 要怎么切？
    *   如果填 1，内部就不切（纯平的）。如果填很大，不仅边缘切碎，内部也会长出像蜘蛛网一样密密麻麻的新三角形。

*(注：如果你切的是四边形Quad，`edge` 就会变成 4 个，`inside` 就会变成 2 个（横向内部切几刀，纵向内部切几刀）。)*

---

### 3. `patchConstantFunction` 是干什么的？ ——（经理的统筹办公室）

**通俗理解：整个面片的“统筹决策会议”。**

在 Hull Shader 代码里，其实有两个函数。一个是主函数 `hull(...)`，另一个就是被 `[patchconstantfunc("...")]` 标签绑定的 `patchConstantFunction`。

**为什么非要分两个函数这么麻烦？这是为了极致的性能！**

*   **主函数 `hull`（工人干活）**：每个控制点（角）跑一次。三角形有 3 个角，它就**跑 3 次**。用来把原始的点原封不动地交接给下一道工序。
*   **`patchConstantFunction`（经理决策）**：每一个面片（三角形），它只**跑 1 次**！

**它的神级作用（面试满分回答）：计算自适应 LOD 细分！**
你绝对不会在真实游戏里，把所有三角形都固定切 4 刀（像我们上一问那样写死）。你会在这里做复杂的**数学统筹**。

**典型的 `patchConstantFunction` 内部的高级逻辑是这样的：**
```hlsl
// 这是在这个函数里经常写的黑科技代码：
TessFactors patchConstantFunction (InputPatch<v2h, 3> patch)
{
    TessFactors f;
    
    // 1. 拿到三角形三个角的 3D 世界坐标
    float3 p0 = mul(unity_ObjectToWorld, patch[0].vertex).xyz;
    float3 p1 = mul(unity_ObjectToWorld, patch[1].vertex).xyz;
    float3 p2 = mul(unity_ObjectToWorld, patch[2].vertex).xyz;

    // 2. 算一下这个三角形的中心点在哪
    float3 center = (p0 + p1 + p2) / 3.0;

    // 3. 算一下这个三角形中心，离当前的摄像机有多远？
    float dist = distance(center, _WorldSpaceCameraPos);

    // 4. 【核心动态决策】
    if (dist < 5.0) {
        // 离得特别近（5米内），给我往死里切！切 32 刀！显示石头缝隙的完美细节！
        f.edge[0] = f.edge[1] = f.edge[2] = f.inside = 32;
    } 
    else if (dist < 20.0) {
        // 离得中等距离，切个 8 刀意思一下
        f.edge[0] = f.edge[1] = f.edge[2] = f.inside = 8;
    } 
    else {
        // 离得几十米远，人跟蚂蚁一样小，切个屁，全部设为 1（不细分）！性能拉满！
        f.edge[0] = f.edge[1] = f.edge[2] = f.inside = 1;
    }

    // 甚至你还可以判断：如果这个三角形在屏幕外（Frustum Culling），直接输出 f.edge = 0，
    // 这样接下来的硬件切面机会直接把这个三角形“蒸发”掉，一刀不切，连画都不画了！

    return f;
}
```

### 总结
*   **`InputPatch`**：打包送进来的 3 个点的原数据。
*   **`patchConstantFunction`**：针对这 3 个点组成的三角面，偷偷做一次全局计算（算距离、算朝向）。
*   **`TessFactors` / `edge` / `inside`**：计算完毕后得出的结果填进此处，直接塞给光栅化电路，让死板的机器听从你的智慧安排。
