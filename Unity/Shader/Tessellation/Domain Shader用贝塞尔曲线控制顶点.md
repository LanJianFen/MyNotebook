

你这个问题，彻底推开了**“次世代游戏图形学（Next-Gen Graphics）”**最硬核的那扇大门！

当 Hull Shader 真的输出了 10 个控制点时，Domain Shader 里的那句简单的 `A*u + B*v + C*w` 就彻底失效了。因为 10 个点根本没法用简单的线性加法来算！

这时候，Domain Shader 必须祭出图形学史上最伟大的数学公式之一：**伯恩斯坦多项式（Bernstein Polynomials）**，或者通俗点叫**“三次贝塞尔三角形（Cubic Bézier Triangle）公式”**。

让我带你看看这 10 个点是如何在 Domain Shader 里发力的。

---

### 一、这 10 个“引力磁铁”是如何分布的？

在提取公式之前，我们先看看 Hull Shader 传过来的这 10 个点（`patch[0]` 到 `patch[9]`）到底在空间中扮演什么角色：

1. **3 个角点（Corners）**：就是原来低模的 3 个角。
2. **6 个边缘点（Edges）**：每条边上有 2 个悬空的控制点，负责把原来笔直的边**向外拉弯**。
3. **1 个中心点（Center）**：悬浮在三角形正上方的半空中，负责把整个三角形的“肚皮”**向上吸起**。

---

### 二、新顶点坐标的计算（极其华丽的引力交响乐）

当切面机（Tessellator）把纯百分比坐标 `bary (u, v, w)` 传给 Domain Shader 时，Domain Shader 会通过一个极其复杂的“非线性引力公式”，算出新顶点的 3D 坐标。

代码长这样（**极其硬核，但这正是显卡每天在算的东西**）：

```hlsl
[domain("tri")]
v2f ds(
    TessellationFactors factors,
    float3 bary : SV_DomainLocation, 
    const OutputPatch<v2h_ControlPoint, 10> patch // 接收 10 个控制点
) {
    v2f output;
    
    // 把 u, v, w 提取出来方便写公式 (保证 u+v+w = 1.0)
    float u = bary.x;
    float v = bary.y;
    float w = bary.z;

    // 【1. 计算 3D 坐标：三次贝塞尔三角形公式】
    // 这里不再是简单的相乘，而是 u,v,w 的三次方和混合乘积！
    
    // 角落的引力 (三次方)
    float3 pos = patch[0].pos * (u * u * u) + 
                 patch[1].pos * (v * v * v) + 
                 patch[2].pos * (w * w * w) +
                 
                 // 边缘的引力 (混合二次方) - 乘以 3 是数学上的组合数权重
                 patch[3].pos * (3.0 * u * u * v) + 
                 patch[4].pos * (3.0 * u * v * v) + 
                 patch[5].pos * (3.0 * v * v * w) + 
                 patch[6].pos * (3.0 * v * w * w) + 
                 patch[7].pos * (3.0 * w * w * u) + 
                 patch[8].pos * (3.0 * w * u * u) +
                 
                 // 中心的引力 - 乘以 6，负责鼓起整个弧面！
                 patch[9].pos * (6.0 * u * v * w);
                 
    output.pos = UnityObjectToClipPos(pos); // 算完后推向屏幕
    ...
}
```
**看懂魔法了吗？**
如果这个新顶点正好在正中心（`u=0.33, v=0.33, w=0.33`），那么公式最后一行的 `6 * u * v * w` 就会发挥极大的权重，`patch[9]`（那个悬空的中心磁铁）就会狠狠地把这个新顶点**拉向半空中**！于是，平面的三角形就被“吹胀”成了圆润的立体表面。

---

### 三、那 UV 和 法线 怎么办？也用 10 个点算吗？

**不！这就是 3A 游戏优化最狡猾、最聪明的地方。**

#### 1. 关于 UV 坐标（降维打击，只用 3 个点）
如果在曲面上贴图，我们希望贴图是**均匀平铺**的。如果我们把 UV 也用 10 个点拉扯，那贴图就会严重扭曲（像哈哈镜一样）。
所以，哪怕我们接收了 10 个控制点，Domain Shader 在算 UV 的时候，**依然只用最原始的那 3 个角点进行简单的线性加法！**

```hlsl
    // 【2. 计算 UV：大道至简】
    // 根本不去管那悬浮的 7 个点，老老实实按 3 个角的比例混合，保证贴图不扭曲
    output.uv = patch[0].uv * u + patch[1].uv * v + patch[2].uv * w;
```

#### 2. 关于法线 Normal（可以用 6 个点，也可以退回 3 个点）
法线比较特殊，因为表面弯曲了，法线（朝向）也必须跟着弯曲，光照才显得真实。
* **低性能/普通画质**：直接和 UV 一样，用 3 个原始法线做线性混合（`A*u + B*v + C*w`）。
* **极高画质（PN-Triangles 完整版）**：不用 10 个点，而是基于 3 个角点的原始法线，再在 Hull Shader 里额外交代 **6 个法线控制点**（组成一个二次贝塞尔公式）。但在很多商业引擎里，为了省性能，我们通常就直接在算完 `pos` 后，让 Domain Shader 通过周围点的差值**重新计算一遍法线**，或者依然只用 3 个角来插值。

### 总结

当你把输出调成 10 个控制点时，Domain Shader 的工作状态发生了裂变：

1. **算坐标（Pos）**：火力全开！调动全部 10 个点，用极其华丽的“三次贝塞尔多项式公式”，把平原拉扯成山丘。
2. **算贴图（UV）**：冷酷无情。无视那 7 个新建的控制点，依然用 3 个角的线性比例算 UV，确保表面的衣服图案不走样。
3. **算光照（Normal）**：看性能余额。余量足就跟着曲面法线公式走，不够就凑合用 3 个原始角的法线。

这就是 GPU 里 Domain Shader 的顶级指挥艺术：**该复杂的地方（几何形体）疯狂算数学题，该简单的地方（贴图）能省则省。** 这种机制，造就了今天游戏里无比圆润平滑的模型边缘！
