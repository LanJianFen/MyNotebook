
Scale = -1 的时候，传递给顶点着色器的坐标和法线有什么变化，Scale和副切线的朝向有什么关系

这是一个非常硬核的几何数学问题！我们需要像做外科手术一样，把你提到的数据流（从 Mesh 到 Vertex Shader）切开来看。

核心结论先行：
1.  **传递给顶点着色器的数据（Input）**：**完全没变**。
2.  **顶点着色器算出来的结果（Output）**：位置翻转了，法线翻转了。
3.  **Scale 和副切线的关系**：Scale 为 -1 会导致数学计算出的副切线和纹理实际需要的副切线**方向相反**。

我们分三步详细解释：

---

### 1. 传递给顶点着色器的数据有变化吗？

**没有任何变化。**

*   **v.vertex (模型空间坐标)**：这是这种模型文件（.fbx/.obj）里存死的。不管你在 Inspector 里怎么改 Scale，Mesh 内存里的数据是不变的。
    *   比如顶点 A，在模型里坐标是 `(1, 1, 1)`。
    *   即使 Scale = `(-1, 1, 1)`，传入 Shader 的 `v.vertex` 依然是 `(1, 1, 1)`。
*   **v.normal (模型空间法线)**：同理，也是存死的。
    *   如果法线朝右 `(1, 0, 0)`，传入 Shader 的依然是 `(1, 0, 0)`。

**变化发生在“矩阵乘法”这一步：**
```hlsl
// 在这一步，Scale 只有参与了运算，坐标才变成了世界空间的 (-1, 1, 1)
float4 worldPos = mul(unity_ObjectToWorld, v.vertex); 
```

---

### 2. Scale 和 副切线 (Bitangent) 的恩怨情仇

这是问题的核心。为什么 Scale = -1 会搞坏法线贴图？

我们需要引入 **TBN 矩阵（由切线、副切线、法线组成的坐标系）**。
你可以把它想象成生长在模型表面每一个点上的“小坐标系”，用来指示法线贴图的“上、下、左、右”。

#### A. 正常情况 (Scale = 1)
根据数学定义（右手定则），副切线 **B** 是通过法线 **N** 和切线 **T** **叉乘 (Cross Product)** 算出来的：
$$ B = N \times T $$

*   假设 **N** 朝上 (Up)
*   假设 **T** 朝右 (Right)
*   根据右手定则，**B** 应该朝前 (Forward)。

#### B. 镜像情况 (Scale = -1) - 此时产生了悖论！

当你把模型 x 轴镜像后：

1.  **几何现实（纹理需要什么）**：
    *   模型被翻转了，贴图的 UV 映射在三维空间中也被“翻面”了。
    *   就像你照镜子，你的左手在镜子里变成了“右手”。
    *   此时，为了让法线贴图正确显示，**副切线 B 实际上应该反过来指**。

2.  **数学计算（Shader 实际上算出了什么）**：
    *   我们在 vertex shader 里计算 `mul` 之后：
        *   世界法线 **N** 翻转了（因为 x 镜像）。
        *   世界切线 **T** 翻转了（因为 x 镜像）。
    *   现在我们来算叉乘 $N \times T$：
        *   根据数学规律：**$(-N) \times (-T) = N \times T$**。
        *   **惊人的发现**：负负得正！数学公式算出来的副切线方向 **竟然没变！**

**出大事了：**
*   **纹理说**：“因为模型镜像了，我的 V 轴（副切线）应该**反向**才能对得上图。”
*   **数学公式说**：“根据叉乘定律，我的方向**不变**。”

结果就是：**算出来的副切线是反的（相对于纹理空间）。**
如果不修正，光照照在法线贴图上，凹凸感就会反转（原本向左的光，计算出来像是从右边照的）。

---

### 3. 如何修正？( `unity_WorldTransformParams.w` 登场)

这就是为什么我们需要这个变量。

Unity 的标准做法是强行干预数学公式：

```hlsl
// 1. 先按标准数学公式算叉乘（此时算出来的 B 在镜像下是错的）
float3 mathBitangent = cross(worldNormal, worldTangent);

// 2. 引入修正系数
// unity_WorldTransformParams.w 在 Scale=-1 时是 -1.0
// v.tangent.w 是模型原本的手性（通常也是 +/- 1.0）
float fixFactor = v.tangent.w * unity_WorldTransformParams.w;

// 3. 修正！如果镜像了，就把方向强行掰回来
float3 realBitangent = mathBitangent * fixFactor;
```

### 总结一张表

假设我们对一个球体进行 X 轴镜像 (Scale = -1, 1, 1)：

| 数据/属性 | 传入 Shader 前 (Appdata) | 经过矩阵变换后 (World Space) | 备注 |
| :--- | :--- | :--- | :--- |
| **顶点位置 (P)** | 不变 `(x, y, z)` | 翻转 `(-x, y, z)` | 正常物理表现 |
| **法线 (N)** | 不变 `(x, y, z)` | 翻转 `(-x, y, z)` | 正常物理表现 |
| **切线 (T)** | 不变 `(x, y, z)` | 翻转 `(-x, y, z)` | 正常物理表现 |
| **副切线 (B)** | **不存在于输入中** | **计算值不变** (数学陷阱) | $ (-N) \times (-T) = B $ |
| **实际需要的 B** | - | **应该翻转** | 需与 UV 镜像匹配 |
| **最终 B** | - | **翻转** | 乘以了 `unity_WorldTransformParams.w` |

所以，Scale 和副切线的关系是：**Scale 为负（镜像）时，会导致数学计算出的副切线与纹理空间不一致，必须乘以 -1 进行修正。**
