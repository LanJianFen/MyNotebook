
==Scale 的 X 变成了-1，是在MVP矩阵里将 M 的 ScaleX 变成 -1==

这是一个非常精彩的“沙盘推演”！把我们前面讲的所有底层知识（镜像UV、切线数据、M矩阵、单数负缩放）全部串联在一起了。

为了不把人绕晕，我们先建立一个共识：
当 `Scale.X = -1` 时，**原本在左边的面片A，物理上跑到了右边；原本在右边的面片B，物理上跑到了左边。**

我们分别来看看 UV、切线（Tangent）和副切线（Bitangent）到底经历了什么“过山车”般的变化。

---

### 第一步：UV 怎么变化？

**答案是：UV 数据连一根毫毛都没有变！**

*   **底层逻辑：** UV 只是记录在顶点里的 2D 坐标 (`TEXCOORD0`)。Transform 的 MVP 矩阵**只对 3D 空间（XYZ）生效，对 UV 绝对不生效**。
*   **面片A（原左侧，现物理右侧）：** 它的顶点虽然被矩阵拍到了世界空间的右边，但它的 U 坐标依然是 `0 -> 1`。
*   **面片B（原右侧，现物理左侧）：** 它的顶点跑到了世界空间的左边，但它的 U 坐标依然是 `1 -> 0`（我们之前设定的镜像UV）。
*   **视觉结果：** 因为带着 `U=0` 的顶点跑到了右边，带着 `U=1` 的顶点还在中间，所以在物理屏幕上，这张贴图被**再次水平翻转**了！

---

### 第二步：切线（Tangent）怎么变化？

切线是一个 3D 方向向量 `(x, y, z)` 加上一个标志位 `w`。
方向向量会参与 M 矩阵的乘法，而 `w` 属于纯数据，**不参与矩阵乘法**。

**1. 面片A（原左侧，现物理右侧）：**
*   **原本：** 切线朝右 `(+1, 0, 0)`，`w = 1`。
*   **经过 M 矩阵（X乘了-1）后：** 切线方向被反转，**变成了朝左 `(-1, 0, 0)`**！
*   **w 分量：** 依然是 `1`。

**2. 面片B（原右侧，现物理左侧）：**
*   **原本（镜像UV导致）：** 切线朝左 `(-1, 0, 0)`，`w = -1`。
*   **经过 M 矩阵（X乘了-1）后：** 负负得正，切线方向**变成了朝右 `(+1, 0, 0)`**！
*   **w 分量：** 依然是 `-1`。

---

### 第三步：副切线（Bitangent）怎么算？（🌟高能推演）

还记得我们在 Shader 里写的终极公式吗：
**`B = Cross(N, T) * v.tangent.w * unity_WorldTransformParams.w`**

已知现在的条件：
*   法线 `N` 始终朝向屏幕外（+Z轴）。
*   因为 `Scale.X = -1`（单数负缩放），CPU 已经紧急将 **`unity_WorldTransformParams.w` 设置为了 `-1`**！
*   我们希望最终算出来的副切线 `B` 依然能**正确地指向上方（+Y轴）**。

我们用这个公式，分别代入现在的 面片A 和 面片B 算一次：

#### 推演 1：面片A（原左侧，现物理右侧）
*   **N（法线）** = `(0, 0, 1)`  [朝外]
*   **T（世界切线）** = `(-1, 0, 0)` [刚才算了，现在朝左]
*   **第一步，叉乘：** `Cross( (0,0,1) , (-1,0,0) ) = (0, -1, 0)`
    *   *糟糕！叉乘出来的结果指向下方（-Y）了！*
*   **第二步，乘标志位：**
    *   面片A自带的 `v.tangent.w = 1`
    *   全局变换参数 `unity_WorldTransformParams.w = -1`
*   **最终计算：** `(0, -1, 0) * 1 * (-1) = (0, 1, 0)`
*   **结果：(+Y) 朝上！** 引擎用 Transform 参数的 `-1`，成功把指向下方的错误副切线，**掰回了正上方**！面片A的光照完美正确！

#### 推演 2：面片B（原右侧，现物理左侧）
*   **N（法线）** = `(0, 0, 1)`  [朝外]
*   **T（世界切线）** = `(1, 0, 0)` [刚才算了，负负得正，现在朝右]
*   **第一步，叉乘：** `Cross( (0,0,1) , (1,0,0) ) = (0, 1, 0)`
    *   *哦？叉乘出来的结果刚好指向上方（+Y），似乎不需要掰了？*
*   **第二步，乘标志位（重头戏来了）：**
    *   面片B因为是镜像UV，自带的 `v.tangent.w = -1`
    *   全局变换参数 `unity_WorldTransformParams.w = -1`
*   **最终计算：** `(0, 1, 0) * (-1) * (-1) = (0, 1, 0)`
*   **结果：(+Y) 依然朝上！** 面片B自带的 `-1` 和 Transform 参数的 `-1` **发生了“负负得正”的魔法抵消**！副切线依然坚挺地指向上方，光照完美正确！

### 总结一张表

假设我们对一个球体进行 X 轴镜像 (Scale = -1, 1, 1)：

| 数据/属性 | 传入 Shader 前 (Appdata) | 经过矩阵变换后 (World Space) | 备注 |
| :--- | :--- | :--- | :--- |
| **顶点位置 (P)** | 不变 `(x, y, z)` | 翻转 `(-x, y, z)` | 正常物理表现 |
| **法线 (N)** | 不变 `(x, y, z)` | 翻转 `(-x, y, z)` | 正常物理表现 |
| **切线 (T)** | 不变 `(x, y, z)` | 翻转 `(-x, y, z)` | 正常物理表现 |
| **副切线 (B)** | **不存在于输入中** | **计算值不变** (数学陷阱) | $ (-N) \times (-T) = B $ |
| **实际需要的 B** | - | **应该翻转** | 需与 UV 镜像匹配 |
| **最终 B** | - | **翻转** | 乘以了 `unity_WorldTransformParams.w` |

### 终极总结

这就是 3D 图形学底层数学的**极致严谨与美感**：

当你在编辑器里顺手敲下 `Scale X = -1` 的那一刻：
1. **UV数据**无动于衷。
2. **切线方向（T）**被空间矩阵粗暴地扭转了。
3. 但就在副切线（B）即将算出错误方向，导致法线贴图阴影全错的生死关头……
4. **顶点数据里的 `w`**（守护着镜像UV的尊严）和 **引擎传入的全局 `w`**（守护着空间缩放的尊严）联合起来。通过巧妙的乘法符号运算，强行纠正了空间法则！

最终你在屏幕上看到的，依然是一个光照正确、完美反射的镜像模型。而这背后，是 Shader 每一帧数百万次的矩阵与向量的精确推演。
