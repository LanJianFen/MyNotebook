

在C++中，继承修饰符（Inheritance Access Specifiers）有三种：`public`（公有）、`protected`（保护）和 `private`（私有）。

你可以把继承修饰符想象成一个**“权限漏斗（或降级过滤器）”**：它不会提升基类成员的权限，它的作用是**控制基类的成员在派生类（子类）中对外展示的最大访问权限**。

作为精通C++的工程师，我为你总结了这三种修饰符的核心机制以及实际开发中的真实应用场景。

---

### 1. 核心规则一览表

假设基类（Base）里有三种成员，当子类（Derived）以不同的方式继承时，这些成员在子类中的权限变化如下：

| 基类成员原本的权限 | `public` 继承 (99%的用法) | `protected` 继承 (极少) | `private` 继承 (少见但有用) |
| :--- | :--- | :--- | :--- |
| **public** | **public** (保持不变) | **protected** (降级) | **private** (降级) |
| **protected** | **protected** (保持不变) | **protected** (保持不变) | **private** (降级) |
| **private** | *子类不可直接访问* | *子类不可直接访问* | *子类不可直接访问* |

*(注：基类的 `private` 成员永远只属于基类自己，无论哪种继承，子类都不能直接访问，只能通过基类提供的 public/protected 函数间接调用。)*

---

### 2. 深入理解与引擎开发中的应用

#### ① `public` 继承：表达 "Is-A" (是一个) 的关系
这是你**最常用**的继承方式，占了日常开发的 99%。它完美保留了基类的接口。

**场景**：在你写的 Hazel 引擎里，用户需要创建一个自己的游戏（比如叫 Sandbox），这个游戏本质上**就是一个** Application。
```cpp
// 引擎核心库中
namespace Hazel {
    class HAZEL_API Application {
    public:
        void Run();        // 所有人都可以调用
    protected:
        void PushLayer();  // 只有引擎内部和子类可以调用
    };
}

// 用户的客户端代码中
class Sandbox : public Hazel::Application {
    // Run() 在这里依然是 public
    // PushLayer() 在这里依然是 protected
};

Sandbox* app = new Sandbox();
app->Run(); // 合法！因为是 public 继承
```

#### ② `private` 继承：表达 "Implemented-in-terms-of" (根据...实现) 
这种继承会把基类所有的公开和保护接口全部“藏起来”，变成子类的私有成员。外部无法知道子类继承了这个基类。

**场景**：它和“组合（包含一个对象）”非常类似，但 C++ 高级程序员用它主要是为了**空基类优化（EBO - Empty Base Optimization）**或需要重写基类的虚函数但又不想暴露基类接口时。
```cpp
class NonCopyable {
protected:
    NonCopyable() = default;
    ~NonCopyable() = default;
private:
    NonCopyable(const NonCopyable&) = delete;
    NonCopyable& operator=(const NonCopyable&) = delete;
};

// Application 私有继承 NonCopyable
// 意味着 Application 禁止拷贝，但外部根本不需要知道 NonCopyable 的存在
class Application : private NonCopyable {
    // ...
};
```

#### ③ `protected` 继承：受限的接口传递
它把基类的 public 接口在子类中变成了 protected。这意味着只有**子类和子类的子类**知道这个继承关系，外部世界完全不知道。这种用法在实际工程中非常罕见，通常只在设计极为复杂的类层次结构中间层时使用。

---

### 3. C++ 中最容易踩坑的“默认行为”

既然你用到了 C++20，一定要记住 `class` 和 `struct` 在继承时的**默认行为是不同的**。这是初学者极易犯错的地方：

如果你忘了写继承修饰符：

**使用 `class` 时，默认是 `private` 继承！**
```cpp
class Sandbox : Hazel::Application {
    // 完蛋了！这里默认是 private 继承。
    // Sandbox 的实例将无法调用 app->Run()，编译器会报错说 Run() 是私有的。
};
```

**使用 `struct` 时，默认是 `public` 继承！**
```cpp
struct Sandbox : Hazel::Application {
    // 合法！默认是 public 继承。app->Run() 可以正常调用。
};
```

**💡 最佳实践建议：**
为了代码的清晰度和可读性，**永远显式地写出继承修饰符**，不要依赖编译器的默认行为。像这样：
`class Sandbox : public Hazel::Application`
