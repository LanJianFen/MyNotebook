

要彻底搞懂 C# 的垃圾回收（GC），我们必须先在脑海中建立一个关键的认知：**C# 的内存分为两个截然不同的区域 —— 栈（Stack）和托管堆（Managed Heap）。**

这两者的回收机制完全不同。

我们用你提到的场景，写一段简单的代码来做一次“内存级别的慢动作回放”：

```csharp
void MyFunction() 
{
    int a = 10;                   // 1. 一个 int
    string b = new string('x', 5); // 2. 一个 string (用 new 避免字符串池干扰)
    MyClass c = new MyClass();    // 3. 一个 class 对象
    
    // 执行一些操作...
} // 函数结束，右大括号 } 
```

当程序执行到这里，内存里到底发生了什么？什么时候被回收？我们分阶段来看。

---

### 第一阶段：分配内存（它们住在哪里？）

在 C# 中，变量的类型决定了它存在哪里：
*   **值类型（Value Type）：** 比如 `int`, `double`, `struct`。它们**直接分配在“栈”上**。
*   **引用类型（Reference Type）：** 比如 `string`, `class`, `数组`。它们的**实体数据分配在“堆”上**，但在“栈”上会留一个“指针（引用）”，指向堆里的实体。

所以在 `MyFunction` 执行时，内存是这样的：
1.  **栈（Stack）上**：压入了三个东西。
    *   `a`：直接存着数字 `10`。
    *   `b`：存着一串内存地址（比如 `0x1111`）。
    *   `c`：存着一串内存地址（比如 `0x2222`）。
2.  **托管堆（Heap）上**：分配了两块内存。
    *   地址 `0x1111` 处：存着真正的字符串数据 `"xxxxx"`。
    *   地址 `0x2222` 处：存着 `MyClass` 真正的对象数据。

---

### 第二阶段：函数结束（第一波瞬间回收）

当程序执行到函数的右大括号 `}` 时，该函数执行完毕，准备返回。

**发生了什么？**
操作系统的 CPU 寄存器（栈指针 ESP/RSP）会瞬间往回弹。**函数的整个“栈帧”被直接抛弃/覆盖。**

**谁被回收了？**
*   `int a`：**瞬间死亡，立刻被回收。**（无需 GC 介入）
*   `string b` 的栈上指针：**瞬间死亡。**
*   `class c` 的栈上指针：**瞬间死亡。**

**谁还没被回收？**
堆上的 `"xxxxx"` 字符串实体，和 `MyClass` 的对象实体，**依然躺在堆内存里，毫无察觉。** 
只是现在，再也没有任何栈上的指针指向它们了。它们变成了断了线的风筝，在 C# 中我们称之为**“不可达对象（Unreachable Objects）”**或直接叫**“垃圾”**。

---

### 第三阶段：GC 登场（第二波延时回收）

此时，`string` 和 `class` 的实体还在占用内存。它们**什么时候**被回收？

答案是：**不知道，取决于虚拟机的“心情”。** 
C# 的 GC 是**非确定性（Non-deterministic）**的。函数结束时，GC 绝不会立刻跑过来清理堆内存，因为频繁清理太消耗 CPU 性能了。

**GC 什么时候会启动？**
1.  **内存不够了**：当程序继续运行，还要 `new` 新对象，发现堆内存达到阈值，或者空间不足时。
2.  **系统内存压力大**：操作系统通知 .NET 运行时内存紧张。
3.  **手动强制调用**：程序员手欠写了 `GC.Collect()`（极度不推荐）。

**GC 是怎么找出垃圾并回收的？（核心算法：标记-清除）**

当 GC 决定启动时，它会做以下三步：

**1. 暂停世界（Stop The World）：**
极短暂地暂停你的 C# 程序运行（通常在几毫秒内），防止在清理时对象关系还在变。

**2. 寻找 GC Root（标记阶段）：**
GC 就像一个顺藤摸瓜的侦探。它从所有的“根（GC Roots）”（包括当前所有活着的线程的**栈**、全局静态变量等）出发，顺着指针去堆里找对象。
*   只要能找到的对象，就打上标记：“这是活人，别动”。
*   因为刚才 `MyFunction` 已经结束，栈上的 `b` 和 `c` 指针已经没了。GC 顺藤摸瓜时，**找不到**地址 `0x1111` 和 `0x2222`。
*   于是，`string` 和 `class` 实体没有被打上存活标记。

**3. 清理与压缩（清除阶段）：**
*   GC 把没有标记的对象（我们的 `string` 和 `class`）所占用的内存直接抹除。**此时，它们真正被回收了。**
*   **内存压缩（碎片整理）：** 就像整理磁盘碎片一样，GC 会把后面活着的对象往前挪，把空出来的内存填满，让堆内存保持连续。（挪动对象后，GC 会自动更新所有指向它们的指针，这也是为什么给 C++ 传指针时必须用 "钉扎(Pinning)" 的原因，防止 GC 乱挪）。

---

### 进阶：C# 工程师必须懂的“代龄（Generations）”机制

为了让 GC 跑得快，微软把堆内存分成了三代：**第 0 代、第 1 代、第 2 代**。

*   **第 0 代（新生代）：** 刚 `new` 出来的对象都在这里。容量很小。
*   **第 1 代：** 熬过一次 GC 没被回收的对象，会升级到这里。
*   **第 2 代（老年代）：** 熬过两次 GC 的对象（比如全局静态字典、长生命周期的服务类），升级到这里。

**你例子中的 `string` 和 `class` 的命运：**
因为它们在一个函数内部定义，生命周期极短。它们出生在第 0 代。
很快函数结束，它们变成了垃圾。
当第 0 代内存满了触发 GC 时，GC 发现它们死了，直接清掉。
**清理第 0 代极快（微秒/毫秒级），这被称为“短暂 GC（Ephemeral GC）”。**

### 总结

回到你的问题，在一个函数里定义的变量，何时回收？

1.  `int`（值类型）：**函数结束（右大括号）的瞬间，伴随栈帧弹出，立刻物理回收。**
2.  `string` 和 `class`（引用类型）：**函数结束的瞬间，它们的“引用/指针”立刻回收；但它们在堆中的“实际数据”，会在未来某次内存分配触发 GC 时，由垃圾回收器在后台静默清理。**

*(注：如果是字面量字符串如 `string b = "hello";`，它会被放入特殊的“字符串拘留池”，伴随整个进程的生命周期，基本不会被回收。上面例子用 `new string()` 是为了说明普通引用类型的回收逻辑。)*
